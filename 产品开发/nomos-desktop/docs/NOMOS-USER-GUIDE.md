# Nomos 操作说明书

> 对齐版本：PRD 0.3 目标模型
> 更新日期：2026-06-20
> 说明：本手册描述 Nomos 的**目标产品模型**（与 `NOMOS-PRD.md` 0.3 一致）。功能按 PRD 第 15 节路线图分阶段上线，文中用状态标记区分：✅ 已上线 / 🚧 开发中 / 🔜 规划中。1.1.0 旧版操作另存于 `NOMOS-USER-GUIDE-v1.1.0-backup.md`。

## 1. 产品用途

Nomos 是一套**以流程为核心**的本地优先企业管理操作系统。你可以：

- 把企业成熟的业务流程沉淀进 Nomos，让它真正被管理、跑起来；
- 用**碳基（人）+ 硅基（智能体）员工**作为流程节点的执行资源；
- 在每个关键节点保持责任、权限、进度和结果透明。

Nomos 管的是**管理层**：组织、岗位、员工、流程、派发、验收、审批、审计。
Nomos 不管智能体的**执行层**：命令执行、工作目录读写、网络访问、智能体的运行与沙箱——这些由企业 IT 负责。对智能体，Nomos 只确认两件事：**连得上 + 可被管理**。

客户数据只保存在本机用户数据目录，不会自动上传网络。

## 2. 核心概念速览

理解这几个概念，就理解了整个产品：

| 概念 | 是什么 |
| --- | --- |
| 智能体连接（ConnectionProfile） | 一个可达、可管理的本地或远程智能体通路（如“本机 Codex”）。**连接 ≠ 员工**。 |
| 岗位（Position） | 组织级、与碳硅无关的稳定角色（如“前端开发工程师”）。捆绑技能、职责、验收标准和管理权限。同一岗位可由人或不同智能体担任。 |
| Skill | 企业用户人工定义、可复用的能力。被岗位引用。 |
| 员工（Employee） | 碳基（人）或硅基（智能体）。**一个员工可身兼多个岗位**；**一个连接可撑多个硅基员工**（会话隔离）。 |
| 流程（Flow） | 产品的核心，承载企业经验。由节点组成，节点声明所需岗位。 |
| 项目（Project） | 某条流程的一次运行实例，承载目标、参与者和工作项。 |
| 工作项（WorkItem） | 可派发的最小工作单元，声明所需岗位。 |
| 回执（Receipt） | 员工提交的结构化执行结果与交付物。 |
| 验收（Acceptance） | 流程节点上由**验收员工**按**验收标准**对交付物的把关。 |
| 权限申请（PermissionRequest） | 员工岗位之外的权限加减，需审批、带有效期。 |

关键关系：**流程**组织**岗位** → 用**员工**去担任岗位 → 员工背后是**智能体连接**。

## 3. 启动客户端

1. 启动 Nomos。
2. 首次启动看到真实空状态，不会自动创建演示项目或虚构员工。
3. 按下面顺序搭起你的组织：接入智能体 → 定义 Skill/岗位 → 创建员工 → 建项目/流程 → 派发。

## 4. 主界面与一级菜单

| 一级菜单 | 用途 |
| --- | --- |
| 控制台 | 经营摘要：在线员工、进行中工作项、待确认派发、待验收交付物、待审批权限申请。所有数字来自实时聚合，无数据显示 0。 |
| 组织 | 员工名录、岗位、数字员工工厂。 |
| 能力池 | 定义和管理 Skill。 |
| 流程 | 流程模板库（含华为体系）、自定义流程、节点。🔜 |
| 派发 | 工作项路由、确认、执行、回执、节点验收。 |
| 项目 | 目标、流程实例、参与者、资料、交付物。 |
| 设置 | Agent 集成、系统、数据范围、备份恢复、安全审计、外观。 |

## 5. 接入智能体（设置 / Agent 集成）✅

进入 `设置 / Agent 集成`，点击新建连接，按向导：

1. **选择位置**：本机 /（远程为后续阶段 🔜）。
2. **选择智能体类型**：Alice、Claude Code、Codex、Kimi、OpenClaw（作为普通智能体）。
3. **检测连接**：自动检测命令或服务，或手动指定命令路径/端点，读取版本。
4. **可管理性与安全检查**：复用官方工具的登录状态，不保存明文密钥；需保管的凭据写入系统安全凭据库。
5. **连接测试**：跑无副作用的可达/可管理性检查，通过才能保存。
6. **命名并保存**：如“本机 Codex”“Mac Studio Claude”。

保存后，这个连接可在数字员工工厂中被选择。

> 注意：这里只配置“连得上、可被管理”。智能体能碰哪些目录、能执行什么命令，由 IT 在智能体侧配置，不在 Nomos。

## 6. 定义 Skill 与岗位

### 6.1 管理 Skill（能力池）✅

1. 进入 `能力池`，新建 Skill。
2. 填写名称、描述、分类、等级、来源。等级是人工设定的标签。
3. 保存后可被岗位引用。
4. 删除被岗位引用的 Skill 会被拦截，并提示关联岗位。

### 6.2 管理岗位（组织 / 岗位）✅

1. 进入 `组织 / 岗位`，新建岗位。
2. 填写名称、岗位族、职责、验收标准。
3. 从 Skill 池选择该岗位需要的技能。
4. 配置岗位的**管理权限**：数据可见范围、职责边界、操作类型、审批要求。
5. 默认岗位可修改但不可删除；被员工或流程引用的岗位删除时会被拦截。

> 岗位与碳硅无关：“前端开发工程师”既可由人担任，也可由 Codex 或 Claude Code 担任。

## 7. 创建员工（组织 / 数字员工工厂）🚧

创建员工是**业务驱动**的动作：因为业务需要某个岗位，才去找智能体来担任。

1. 进入 `组织 / 数字员工工厂`。
2. **Step 1 选择岗位**：选目标岗位（决定技能、职责、验收标准、管理权限），可多选（身兼多岗）。
3. **Step 2 选择类型与连接**：
   - 碳基员工：无需连接。
   - 硅基/混编员工：选一个“可达 + 可管理 + 有并发余量”的连接，系统在其上新起一个隔离会话。无可用连接时引导去 `设置 / Agent 集成`。
4. **Step 3 物化下发**：系统把岗位的技能、职责、验收标准合成提示词，作为该会话的系统提示词下发。
5. **Step 4 入职检查**：连接可达/可管理、只读测试任务、回执格式检查。全部通过进入“可调度”，未通过保存为草稿。

要点：

- **一个连接可撑多个员工**：同一个 Codex 连接可同时担任“前端工程师”和“测试工程师”两个员工，各自独立会话、上下文、回执，互不污染。
- 员工支持暂停调度、恢复、转岗（增减岗位）、离职。离职为软删除，历史工作项不丢失。

## 8. 流程（流程模块）🔜

流程是 Nomos 的核心，承载企业经验。

1. 进入 `流程`，从**模板库**选取或自定义流程。模板库内置华为流程体系（16 个一级流程及其衍生层级）；首批落地**软件开发流程**与**人力资源管理流程**。
2. 每个节点定义名称、目标、输入、输出、依赖、**所需岗位**、路由策略和验收设置（验收员工 + 验收标准）。
3. 流程发布前会校验断链、无人可担任的岗位节点、缺验收标准和循环风险。
4. 已发布的流程版本不可原地改，只能发新版本；正在运行的项目用的是启动时快照的版本，不受影响。

> 现状的五阶段链路（需求→设计→开发→质检→发布）会作为一条**内置模板**保留，不再是写死的全局链路。

## 9. 项目与派发

### 9.1 创建项目 ✅

1. 点击 `+` 新建项目。
2. 填写名称、目标、参与者、时间边界、数据范围、验收定义。
3. 选择一条已发布流程版本，或选自由工作项模式。

### 9.2 派发工作项（派发中心）🚧

1. 进入 `派发`，查看待派发、待确认、执行中、待验收、阻塞、失败的工作项。
2. 派发前，系统展示候选员工、所属岗位、匹配度、负载、连接状态和选择理由。
3. 你可接受推荐或手动改派（改派原因写入审计）。
4. 候选过滤顺序：可调度 → 连接健康可管理 → 担任所需岗位 → 在项目数据范围内 → 有并发余量。

### 9.3 派发本地任务（薄派发透传）✅

Nomos 把任务派给智能体、收回回执；任务在智能体侧怎么执行、用什么授权，由智能体/IT 负责。运行中的任务可取消，失败/中断的可重派。

### 9.4 回执与节点验收 🚧

1. 员工完成后提交结构化回执与交付物，工作项进入“待验收”。
2. 该节点的**验收员工**看到交付物、变更摘要和风险，按**验收标准**选择：通过、补充输入、驳回、退回返工。
3. 返工重派时，系统带上原任务、原回执和验收意见，形成完整证据链。

## 10. 权限申请 🔜

员工的管理权限默认等于其所兼岗位的并集。需要岗位之外的权限时：

1. 发起权限申请，写明原因和期限。
2. 审批人审批（当前单机版为 Owner 自批，仍留痕）。
3. 批准后设定有效期；到期自动回收到岗位基线。

所有岗位外的权限放大都记录原因、授权人和有效期。

## 11. 备份与恢复 ✅

进入 `设置 / 备份与恢复`：

- **创建备份**：在本机数据目录生成 JSON 快照（不含明文凭据）。
- **恢复备份**：检查项目数、员工数、执行记录数后确认。恢复前系统自动创建保护快照；存在待确认、运行中或取消中的任务时拒绝恢复。

## 12. 安全边界

- 客户端默认只绑定本机地址 `127.0.0.1`。
- 凭据保存在系统安全凭据库，不写入 JSON、日志、备份和审计详情。
- 管理级高风险操作（改岗位/权限、审批权限申请、发布流程、批量派发、离职员工、删项目）需人工确认。
- **智能体的执行授权与运行环境由智能体/IT 负责，不在 Nomos**。Nomos 保留工作流级人工关口（节点验收、确认）。
- 备份保存在本机，不会自动上传。

## 13. 常见问题

### 连接和员工是什么关系？

连接代表“这个智能体可用”；员工是“某个智能体担任了某个岗位”。接入一个连接后，不会自动创建员工——你要在数字员工工厂里按业务需要从岗位实例化员工。一个连接可以撑多个员工。

### 为什么 Nomos 不管智能体的目录和命令权限？

那属于执行层，是企业 IT 的职责。Nomos 是管理层操作系统，只确认智能体连得上、可被管理，然后给它派流程里的任务。

### 标了 🔜 / 🚧 的功能现在能用吗？

🔜 表示规划中、🚧 表示开发中，按 PRD 第 15 节路线图分阶段上线。✅ 表示已上线。

### 如何确认数据已备份？

进入 `设置 / 备份与恢复`，检查最新 JSON 快照的时间和文件大小。

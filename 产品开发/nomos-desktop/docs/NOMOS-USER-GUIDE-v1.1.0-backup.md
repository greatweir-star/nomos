# nomos Desktop 1.1.0 操作说明书

## 1. 产品用途

nomos Desktop 是一个本地优先的 Agent 项目指挥台。你可以建立项目目标，查看五阶段交付链路，连接 Alice、Claude Code 和 Codex CLI，并在涉及本地文件、命令执行和发布时保留人工确认权。1.1.0 增加组织管理能力，可以维护 Skill 池、岗位、员工和数字员工草稿。

OpenClaw 默认不初始化、不启动。只有你在本地 Agent 面板中明确接受风险后，系统才会尝试启动它。

## 2. 启动客户端

1. 双击 `nomos-1.1.0-x64.exe`。
2. 首次启动会看到空工作区，不会自动创建演示项目。
3. 点击 `创建第一个项目` 或左上角 `+`。
4. 填写项目名称和本轮目标，点击 `创建项目`。

客户端数据只保存在本机用户数据目录，不会自动上传网络。

## 3. 主界面说明

- 左侧主导航：切换项目总览、协作记录、Agent 团队、项目资料和规则设置。
- 项目列表：切换当前项目；搜索框可以按项目名称、团队或状态说明过滤。
- 项目运行摘要：查看当前阶段、本地 Agent 在线数量、本地任务和人工验收待办。
- 交付链路：点击任一阶段，右侧显示该阶段的执行详情和工作流回执。
- 项目动态：补充需求或查看 Agent 回执。
- 执行详情：查看阶段负责人、项目资料、本地 Agent 状态和本地执行历史。

## 4. 创建和推进项目

### 创建项目

1. 点击左上角 `+`。
2. 输入项目名称。
3. 输入本轮目标。
4. 点击 `创建项目`。

### 推进阶段

点击顶部 `派发任务`，系统会把当前项目推进到下一阶段。

项目默认采用五阶段链路：

1. 需求定义
2. 界面设计
3. 代码开发
4. 质量检查
5. 发布上线

### 提交阶段回执

点击交付链路中的阶段，在右侧 `工作流回执` 区域选择：

- `提交进度`：填写进度百分比和说明。
- `提交成果`：填写成果摘要，可选填交付物名称和链接。
- `标记失败`：记录失败原因，再选择返工路径。
- `退回返工`：把受阻任务退回当前阶段或上游阶段。

## 5. 连接本地 Agent

点击顶部 `接入本地 Agent`、`Agent 团队`，或左下角 `管理`。

面板会检测：

- Alice：本地总管和 MCP 协作入口。
- Claude Code：本地 CLI 执行器。
- Codex CLI：本地代码执行器。
- OpenClaw：桌面操作网关，默认保持未启动。

你可以修改 Agent 显示名称，然后点击 `保存 Agent`。

## 6. 派发本地任务

在右侧 `本地执行` 区域：

1. 选择支持执行的 Agent。
2. 点击 `只读分析` 或 `代码写入`。
3. 填写本地工作目录和任务说明。
4. 检查权限和任务预览。
5. 确认执行。

注意：

- 新目录首次使用时需要单独授权。
- `代码写入` 会要求二次确认。
- 运行中的任务可以取消。
- 失败、取消或中断的任务可以重新执行。

## 7. Alice 协作

在右侧 `工作流回执` 中点击 `派发给 Alice`：

1. 填写可选的协调说明。
2. 检查即将发送给本机 Alice MCP 的内容。
3. 点击确认派发。
4. Alice 完成工作后，点击 `同步 Alice 回执`。
5. 选择 Alice 会话 ID，将结构化结果写回当前阶段。

## 8. 项目资料与设置

### 项目资料

进入 `项目资料`：

1. 选择资料类型。
2. 选择关联阶段。
3. 填写资料名称。
4. 可选填链接。
5. 点击 `添加资料`。

### 规则与权限

进入 `规则与权限`，可以：

- 修改项目名称、团队、状态说明、目标和验收时间。
- 配置 Claude Code 或 Codex CLI 的命令入口。
- 撤销不再使用的额外授权目录。
- 查看最近审计记录。
- 删除当前项目。

## 9. 组织管理

进入 `组织` 页面后，可以在顶部子导航中切换 `概览`、`Skill 池`、`岗位`、`员工` 和 `数字员工工厂`。

### 快速开始

1. 进入 `组织` 页面。
2. 在概览中点击 `快速开始`。
3. 系统会按 7 大岗位族生成默认 Skill 和岗位。
4. 生成后可以继续编辑、补充或创建自己的岗位。

默认模板只会初始化一次。已有默认岗位时，再次初始化会被系统拦截。

### 管理 Skill

1. 进入 `Skill 池`。
2. 点击新建按钮，填写名称、描述、分类、等级和来源。
3. 保存后，Skill 可被岗位引用。
4. 删除被岗位引用的 Skill 时，系统会提示关联岗位并阻止删除。

### 管理岗位

1. 进入 `岗位`。
2. 创建岗位时填写名称、岗位族、类型、职责和验收标准。
3. 从 Skill 池中选择岗位需要的 Skill。
4. 可在流程关联说明中填写如 `LTC/线索管理/R` 这样的自由文本，供后续流程管理迁移。
5. 默认岗位可以修改，但不可删除。

### 管理员工

1. 进入 `员工`。
2. 新建员工时选择碳基、硅基或混编。
3. 碳基员工可不绑定 Agent。
4. 硅基和混编员工需要选择已有 Agent，并可绑定一个或多个岗位。
5. 删除员工会改为离职状态，数据不会被物理删除。

### 数字员工工厂

1. 先创建一个硅基或混编员工。
2. 进入 `数字员工工厂`，选择该员工。
3. Step 1 `岗位匹配`：选择目标岗位，配置 Skill 等级、输入输出、验收标准和职责边界。
4. Step 2 `入职培训`：记录知识库引用、业务语料、行业规则和历史案例。
5. Step 3 `师父带教`：维护 SOP、示范样例和可选师父。
6. 完成前三步后，员工会标记为草稿完成，等待后续版本继续分配工具和转正上岗。

步骤 4-6 在当前版本中显示为即将推出。

## 10. 本地备份与恢复

进入 `规则与权限`，找到 `本地数据备份`。

### 创建备份

1. 点击 `创建本地备份`。
2. 在弹窗中确认。
3. 系统会在本机数据目录生成 JSON 快照。

### 恢复备份

1. 在备份列表中点击 `恢复`。
2. 检查项目数、Agent 数和执行记录数。
3. 确认恢复。

恢复前，系统会自动创建一份保护快照。存在待确认、运行中或取消中的本地任务时，系统会拒绝恢复。

## 11. 安全边界

- 客户端默认只绑定本机地址 `127.0.0.1`。
- 本地文件写入需要明确确认。
- 新目录访问需要明确授权。
- OpenClaw 默认不初始化、不启动。
- OpenClaw 只有在你接受风险声明后才会尝试启动本地网关。
- 备份保存在本机，不会自动上传。

## 12. 常见问题

### 点击按钮没有反应

确认使用的是 `1.1.0` 或更高版本。`1.1.0` 继续使用应用内弹窗处理确认、输入、派发、备份和恢复。

### 首次打开仍看到旧演示项目

旧版本创建的数据会保留在当前用户的数据目录中。可以在项目设置中逐个删除旧项目，或使用全新的 Windows 用户目录启动修正版。

### OpenClaw 为什么显示待配置

这是正常状态。为避免高权限网关意外启动，nomos 不会自动初始化 OpenClaw。

### 如何确认数据已备份

进入 `规则与权限`，在 `本地数据备份` 列表中检查最新 JSON 快照的时间和文件大小。

# Nomos V1.2 流程管理验收报告

## 基本信息

- 版本：1.2.0
- 验收日期：2026-06-11
- 验收范围：流程管理模块（流程库、流程模板 CRUD、项目绑定流程、关口评审）、v1.0.1 与 v1.1 回归能力
- 源码目录：`产品开发/nomos-desktop`
- 关联 PRD：`产品规划/02-PRD/PRD_V1_FLOW_MANAGEMENT.md`

## 验收结论

V1.2 流程管理模块达到开发验收条件。本版让"流程"从硬编码的五阶段交付链路，升级为
用户可定义、可复用、可绑定到项目的流程模板，并引入带准入准出标准的关口评审状态机。
现有五阶段工作流状态机（`workflow.js`）保持不变，流程实例（`flowStages`）作为其并行扩展，
向后兼容——不绑定流程模板的项目行为与 v1.1 完全一致。

## 自动化验证

命令：

```bash
cd 产品开发/nomos-desktop
npm test
```

结果：

- **47 项通过，0 项失败**
- 新增 6 个流程管理测试套件：
  1. 流程模板全量 CRUD（含空名校验、非法分类校验、同名 409、列表/分类筛选、改名）
  2. 预设模板初始化（一次创建 LTC/IPD/ITR 三条，二次调用幂等拦截 409）
  3. 项目绑定 / 更换 / 解绑流程模板，使用计数（usageCount）正确
  4. 关口评审状态流转：pass 进入下一阶段、fail 停留当前、rework 回退指定阶段并重置下游
  5. 删除被项目引用的流程模板 → 409，返回引用项目清单
  6. 向后兼容：无模板项目 `flowTemplateId=null`、`flowStages=[]`、五阶段不变；v7→v8 迁移
- 顺序约束验证：非当前阶段不可评审；未绑定流程的项目评审被拒绝。

## 数据与存储

- 沿用单一 `nomos-data.json`，新增 `flowTemplates[]` 数组；`projects[]` 增加
  `flowTemplateId` 与 `flowStages[]` 字段。
- 数据版本 v7 → v8，`migrateData()` 自动补全字段并规范化历史数据，向后兼容。

## 前端改进

- 修复了组织等页面引用未定义 CSS 变量（`--border` / `--surface` / `--primary` / `--text`）
  导致样式退化的问题，统一映射到既有的雅致绿色调色板。
- 新增"流程"导航页：流程库卡片浏览、模板详情（阶段/关口/输入输出）、项目实例关口追踪
  （带状态色与一键评审）。
- 新建项目弹窗支持可选绑定流程模板。

## 当前边界（留到后续版本）

- 流程模板编辑器为基础可用版（表单创建 + 详情查看），未做阶段拖拽排序、关口可视化编排、
  角色 RACI 绑定的图形化配置——留到后续迭代增强。
- 关口评审为状态机驱动，准入准出条件是文本描述，不做可执行规则引擎（符合 PRD 不做范围）。
- 硅评审 / 碳硅评审目前按动作记录评审人与类型，未接入 Agent 自动校验——留到 v2.0 Workflow
  引擎升级时与碳硅节点标注一并实现。
- 流程实例与五阶段交付链路（`workflow.js`）是两套并行结构，尚未打通"流程阶段 ↔ 交付阶段"
  的自动联动——留到 v2.0 动态编排。

## 结论

V1.2 可发布。建议发布目录命名为 `产品发布/v1.2.0`，并保留既有发布目录不可变。

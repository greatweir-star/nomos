# nomos Desktop 1.2.0

## 本次版本

`1.2.0` 是流程管理版，在 `1.1.0` 组织管理基础上，补齐流程模板库、可视化流程编辑器、项目绑定流程、关口评审和实例追踪能力。

## 新增能力

- **流程模板库**：支持创建、编辑、删除、复制流程模板，按价值流 / 使能流 / 支撑流三级分类，支持搜索和筛选。（路径：流程 > 流程库）
- **流程模板编辑器**：可视化编辑阶段序列，配置关口评审（准入条件 / 准出标准），每个阶段可定义角色责任和输入输出。（路径：流程库 > 编辑模板）
- **流程实例运行**：项目绑定流程模板后，按模板阶段序列运行，支持阶段推进、关口评审、退回返工。（路径：项目详情 > 流程阶段）
- **流程实例追踪**：独立追踪面板，展示所有运行中的流程实例，阶段时间线可视化。（路径：流程 > 实例追踪）
- **默认模板**：内置 "LTC 轻量版"（线索管理 → 商机评估 → 方案设计 → 合同签订）和 "项目交付"（需求定义 → 方案设计 → 开发实施 → 验收交付），开箱即用。（路径：流程库 > 使用预设模板）
- **项目绑定流程**：创建项目时可选流程模板，系统自动实例化阶段序列；未选择则继续沿用现有自由模式。（路径：新建项目 > 选择流程模板）
- **关口评审**：每个阶段支持配置关口，评审方式包括碳评审（人工）、硅评审（Agent 自动校验）、碳硅评审（Agent 预审 + 人工终审），评审结果支持通过 / 不通过 / 需返工三种状态。

## 保留能力

- 组织管理：Skill 池、岗位、员工、数字员工工厂、组织健康度。
- 项目五阶段交付链路（未绑定流程模板的项目行为不变）。
- Windows x64 便携客户端。
- 本机 HTTP 后端和 JSON 持久化，无需额外数据库。
- Alice MCP、Claude Code、Codex CLI、本地执行预览、二次确认、取消、重试和回执。
- 本地备份、恢复预览、恢复前保护快照和活动任务恢复拦截。

## 升级前注意事项

1. **备份数据**：升级前建议通过「设置 > 备份与恢复」创建一次完整备份。v1.2.0 将 `nomos-data.json` 从 v7 升级到 v8，虽然迁移逻辑已覆盖回归测试，但备份是最佳实践。
2. **不绑定流程的项目不受影响**：现有项目和未选择流程模板的新项目，继续沿用 v1.1 的五阶段交付链路，行为完全不变。
3. **流程模板删除限制**：如果一个流程模板已被项目绑定，删除时会收到提示，需要先解绑或更换模板。

## 技术变更说明

- 数据版本：`nomos-data.json` 从 v7 升级到 v8，自动补全 `flowTemplates: []`。
- 新增数据实体：`flowTemplates`（流程模板数组）和 `flowInstances`（运行中的流程实例数组）。
- 后端模块：新增 `backend/flow-api.js`（约 400 行），集中处理流程模板 CRUD、流程实例生命周期和关口评审 API。
- API 路由：`server.js` 新增 18 个路由，覆盖 `/api/flow/templates/*`、 `/api/flow/instances/*` 和 `/api/flow/gate/*`。
- 前端代码：`renderer/app.js` 新增约 500 行，覆盖流程库页面、模板编辑器、实例追踪面板和评审交互组件。
- 向后兼容：项目模型扩展 `flowTemplateId` 和 `flowStages` 字段，未定义时行为与 v1.1 完全一致。

## 已知限制（v1.2 不做范围）

- 不做 L2-L5 五级完整分层，留到 v2.0 Workflow 引擎升级。
- 不做碳硅节点标注，留到 v2.0。
- 不做跨流程编排和子流程调用。
- 不做流程仿真、瓶颈分析和 SLA 监控。
- 不做流程版本 diff 和变更历史。
- 不做规则引擎：准入准出条件为文本描述，不做可执行的规则校验。
- 不做流程模板市场或跨企业共享。
- 数字员工工厂仍为前三步，后续步骤留到 v2.1。
- 当前版本仍是本地优先单机客户端，尚未接入远程账号、云端同步和团队协作服务。

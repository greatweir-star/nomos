# Nomos V0.0.3 智能体交接说明

> 用途：将本版本材料直接分发给前端、后端、测试智能体，减少二次解释和范围漂移。

## 1. 所有智能体共同规则

1. 先读本目录 `README.md`、版本 PRD、总体架构，再读自己的任务包。
2. `NOMOS-PRD.md` 是产品逻辑真源；本版本材料是范围和工程执行基线。
3. 不实现“明确不做”内容，不顺手重构未分配模块。
4. 不修改其他智能体拥有的文件；需要跨模块变化时先提交合同变更说明。
5. 生产模式不得添加虚假数据、固定指标、伪成功或吞错。
6. 所有实现必须附测试和未完成项；“能运行”不等于“满足验收”。

- 将 Agent 集成重新放回一级菜单。

## 4. 测试智能体任务指令

### 必读

- 版本全部材料，重点为测试策略和验收矩阵。

### 领取方式

测试不等待开发结束。先完成 QA-001/002 和失败用例，再随每个领域建立 API/合同测试，最后串联 E2E。

### 独立性要求

- 不以开发自测结果替代测试结论。
- 对无法获得的真实 Connector 环境标记“未验证”，不得记为通过。
- 缺陷必须绑定需求、任务、用例、环境、复现步骤和发布影响。
- 最终报告必须给出允许或不允许发布。

### 回传模板

```md
测试任务 ID：
覆盖需求/任务：
环境与数据夹具：
通过/失败/阻塞：
新增缺陷：
回归范围：
未覆盖风险：
发布建议：
```

## 5. 冲突升级规则

- 产品语义不清 → 产品经理。
- 模块、数据、API、迁移或安全冲突 → 架构师。
- 优先级、排期、文件所有权或依赖冲突 → 研发项目经理。
- 验收标准无法测试 → 产品经理 + 测试共同修订，开发不得自行降低标准。

## 6. 第一批可直接分发任务

- 前端：FE-001、FE-002、FE-003。
- 后端：BE-001、BE-002、BE-003。
- 测试：QA-001、QA-002，并开始 TC-IA-001/002、TC-MIG-001 的自动化设计。

第一批完成后必须先过 M1 联合评审，再进入 ConnectionProfile 功能；这能把后续并行开发建立在稳定壳、数据库和合同上。

# Nomos V0.0.3 测试策略与用例

> 测试目标：证明对象边界、状态一致性、数据安全和核心用户闭环真实可用，而不只证明接口返回 200。

## 1. 测试分层

| 层级 | 责任 | 范围 | 每次提交要求 |
| --- | --- | --- | --- |
| 单元测试 | 开发 | 领域规则、状态机、过滤排名、脱敏 | 相关模块必跑 |
| 集成测试 | 后端/测试 | API、SQLite、事务、迁移、备份 | PR 必跑 |
| Connector 合同 | 后端/测试 | 四类连接的统一行为 | Connector 变更必跑 |
| 前端组件/路由 | 前端 | 状态、表单、错误、可访问性 | 前端 PR 必跑 |
| E2E | 测试 | 核心旅程和高风险操作 | 每日与发布候选 |
| 手工探索/UAT | 测试/产品 | 文案、认知、异常恢复、真实环境 | 每迭代验收 |

## 2. 测试环境与数据

- macOS Apple Silicon 开发、打包与发布环境一套；Windows 暂不进入 V0.0.3 发布范围。
- 空数据、合法旧 v9 数据、含歧义引用 v9 数据、损坏数据四类夹具。
- Codex/Claude/Kimi/Alice 使用真实可用环境至少完成一次合同验收；CI 使用受控 fake connector。
- 测试数据必须有命名空间，禁止写入用户实际工作区。
- 敏感字段夹具使用假 token，用于验证 API、日志、备份和诊断均不泄露。

## 5. 负面和恢复测试

- Connector 超时、输出不符合 schema、进程异常退出、回执重复或乱序。
- 数据库锁、磁盘空间不足、应用异常退出、WAL 恢复。
- 409 乐观锁冲突、重复点击、浏览器刷新、Electron 重启。
- 员工离职、岗位停用、连接降级发生在派发预览与确认之间。
- FlowVersion 被停用但已有项目仍在运行。
- 验收员工缺失、交付物链接失效、返工目标不可用。

## 7. 缺陷等级与发布规则

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 数据丢失、越权、泄密、核心闭环不可用、无法启动 | 必须关闭 |
| P1 | 主流程错误、状态不一致、无恢复路径、关键可访问性阻断 | 必须关闭 |
| P2 | 有绕行的局部问题、明显体验缺陷 | 需产品经理书面接受 |
| P3 | 文案和低频视觉问题 | 可进入后续版本 |

## 8. 测试完成定义

- 所有 P0/P1 用例有自动化或明确手工证据。
- P0/P1 缺陷为 0，P2 有负责人和计划。
- 核心 E2E 在空数据和迁移数据各跑一次。
- 测试报告明确给出“允许/不允许发布”，不只罗列通过数。

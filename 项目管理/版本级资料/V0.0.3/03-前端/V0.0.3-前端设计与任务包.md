# Nomos V0.0.3 前端设计与任务包

> 前端目标：让用户围绕真实流程运行完成配置、派发和验收，而不是浏览一组 Agent 演示卡片。

## 1. 前端技术基线

- React + TypeScript + Vite，新旧页面渐进共存。
- 路由按一级菜单拆分；领域功能不得集中到单一 `app.tsx`。
- API 类型从冻结 OpenAPI/JSON Schema 生成或集中维护，禁止页面自造字段。
- 服务端状态使用统一 query/mutation 层；局部交互使用 feature state。
- 所有页面必须实现 loading、empty、error、permission、conflict 五类状态。

## 2. 信息架构

| 一级菜单 | 二级页面 | 关键动作 |
| --- | --- | --- |
| 控制台 | 经营摘要、待办、异常 | 下钻真实员工/工作项/验收/审批 |
| 组织 | 员工名录、岗位、数字员工工厂 | 创建、入职、暂停、离职、岗位维护 |
| 能力池 | Skill 列表、详情 | 创建、编辑、停用、查看引用 |
| 流程 | 模板库、流程设计、版本 | 校验、发布、停用、查看引用 |
| 派发 | 待派发、执行中、待验收、异常 | 预览、确认、取消、验收、返工 |
| 项目 | 项目列表、运行视图、资料和动态 | 创建、启动、查看节点和工作项 |
| 设置 | Agent 集成、系统、数据、备份、安全、外观 | 检测连接、迁移、备份、审计 |

## 3. 关键页面规格

### FE-SHELL：应用壳

- 一级导航严格为七项；集成不再作为一级入口。
- 保留统一面包屑、页面标题、全局错误提示和任务状态提示。
- 响应范围以桌面 1280×720 至 1920×1080 为主；低于 1180 宽时允许侧栏折叠，不允许内容横向溢出。

### FE-INT：Agent 集成向导

六步：位置 → 类型 → 检测 → 可管理性检查 → 无副作用测试 → 命名保存。

必须展示：检测来源、版本、当前状态、并发容量、最近检查时间和失败原因。不得展示或回传明文凭据，不得出现工作目录授权、执行模式或“自动启动网关”。

### FE-ORG：组织和数字员工工厂

- 员工列表：类型、岗位、状态、连接、负载、当前工作、最近回执。
- 岗位详情：Skill、职责、验收标准、管理权限和引用关系。
- 四步员工向导：选择岗位 → 选择类型/连接 → 审阅岗位提示词快照 → 入职检查。
- 同一连接可以再次创建员工；UI 必须提示会话隔离和并发余量。
- 入职失败保存草稿并显示可修复原因，不进入可调度列表。

### FE-FLOW：流程

- 模板库只显示真实持久化模板；样例有明确标识。
- 编辑器支持节点、连线、岗位槽位、输入输出、验收标准和返工目标。
- 发布前显示断链、环、缺岗位和缺验收标准；P0 问题阻止发布。
- 已发布版本只读；修改必须创建新草稿版本。

### FE-PRJ：项目运行

- 创建项目选择已发布 FlowVersion 或自由工作项模式。
- 运行页展示版本快照、节点状态、每个岗位槽位对应的工作项、参与员工、资料和证据。
- 从项目页可以进入派发和验收，但不能修改全局岗位或流程版本。

### FE-DSP：派发与验收

- 列表按待派发、待确认、执行中、待验收、阻塞/失败分组。
- 派发预览显示候选员工、岗位、连接、负载、匹配原因和不可选原因。
- 确认后立即禁用重复操作并显示稳定 dispatchId。
- 回执页分开展示执行事实、交付物、测试、风险和验收标准。
- 验收动作：通过、补充输入、驳回、返工；非通过必须填写原因。

### FE-DASH：控制台

- 只展示 API 聚合：可调度员工、进行中工作项、待确认、待验收、待审批和异常。
- 每个数字可下钻；无数据展示 0 和一个明确下一步。
- 不使用硬编码模板、固定告警、随机负载或伪更新时间。

## 4. 交互与可访问性标准

- 键盘可完成导航、表格行操作、向导、确认和验收。
- 焦点可见；弹窗打开后焦点进入，关闭后返回触发控件。
- 状态不能只靠颜色；同时提供文本和图标语义。
- 图标按钮必须有 accessible name，不使用裸符号作为唯一提示。
- 表单错误在字段旁展示并提供汇总；服务端 409 显示冲突恢复动作。
- 危险操作在确认层明确对象、影响和不可逆性。

## 6. 前端交付约束

- 前端智能体只修改前端范围和必要类型文件，不自行改变 API 语义。
- API 缺失时使用版本包中的 mock，不在页面内伪造业务成功。
- 每个任务提交：变更摘要、页面状态清单、测试结果、截图/录屏证据、未完成项。
- 视觉实现沿用现有企业控制台语言，但信息密度服从任务优先级；不得为了“看起来在运行”填充虚假数据。

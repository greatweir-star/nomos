## 2. 产品 UAT

### UAT-01 空工作区

全新启动后看到真实空状态；用户知道下一步应先接入连接或导入模板；界面中没有虚构员工、负载、流程、告警和回执。

### UAT-02 同连接多员工

保存本机 Codex；创建“前端工程师”和“测试工程师”；两位员工使用同一连接但 sessionKey、岗位提示词、状态和回执互相隔离。

### UAT-03 黄金流程启动

发布“软件需求到交付”版本；创建项目并启动；每个岗位槽位生成唯一责任工作项；项目显示快照版本。

### UAT-04 派发验收闭环

工作项推荐合格员工；Owner 确认派发；收到 completed Receipt 后进入待验收；验收通过可完成，返工会创建新 attempt 并保留旧证据。

### UAT-05 异常和恢复

连接离线后阻止新派发；员工与历史不丢失；重新测试连接后恢复；应用重启后所有状态保持一致。

### UAT-06 迁移和备份

旧 v9 数据先生成 dry-run；确认后迁移；迁移失败可回退；成功后备份、恢复和数据数量/引用检查通过。

## 3. 技术验收门槛

- `/api/v1` 合同与实现一致，状态和错误码稳定。
- 数据库约束、事务和并发幂等测试通过。
- 四类首批 Connector 使用同一合同套件；无法实测的环境必须明确标为未验证，不伪造通过。
- 旧页面与新页面切换无数据破坏；删除旧代码不在本版关键路径。
- API、数据库、日志、审计、备份、诊断均无明文敏感字段。
- macOS 本地构建与 Windows x64 发布构建通过。

## 4. 发布一票否决

出现任一情况不得发布：

- P0/P1 缺陷未关闭。
- 核心 UAT 任一失败。
- 重复确认产生重复执行。
- Receipt 未验收即被标记业务完成。
- 迁移可能覆盖旧数据且无回退。
- 凭据、token、Cookie、确认令牌出现在可导出材料。
- 生产模式仍包含未标记的虚构数据或固定告警。
- 安装包无法启动、备份不可恢复或发布版本不可识别。

## 5. 发布材料

- 版本号、安装包和 SHA256。
- 数据迁移说明、回退方式和已知限制。
- 自动化测试结果、手工 UAT 证据和缺陷清单。
- 第三方依赖和 Connector 验证状态。
- 用户操作说明：首次连接、创建员工、启动流程、派发和验收。

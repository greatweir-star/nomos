# Nomos V0.0.3 后端设计与 API 合同

> 后端目标：提供可事务、可迁移、可审计的本地领域内核，让前端和测试只依赖稳定合同。

## 1. 实现原则

- 路由只做认证、解析、schema 校验和响应映射。
- 业务规则进入 application/domain；数据访问进入 repository。
- 模块不得直接修改其他模块表，通过 command/query 或领域事件协作。
- 所有写操作事务化、幂等并记录脱敏审计。
- Connector 通过统一接口和合同测试接入。

## 2. 核心接口

### 2.1 Integration

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/adapter-templates` | 只读连接器目录 |
| GET | `/api/v1/connection-profiles` | 列表和筛选 |
| POST | `/api/v1/connection-profiles/discover` | 返回发现结果，不持久化 |
| POST | `/api/v1/connection-profiles` | 创建 draft |
| POST | `/api/v1/connection-profiles/:id/test` | 可达/可管理测试 |
| PATCH | `/api/v1/connection-profiles/:id` | 命名、容量和非敏感配置 |
| POST | `/api/v1/connection-profiles/:id/disable` | 禁用并影响员工可调度性 |

创建请求最小字段：`templateId/name/scope/commandOrEndpoint/concurrencyCapacity`。响应不得返回凭据，只返回 `credentialState`。

### 2.2 Organization

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET/POST | `/api/v1/skills` | Skill 查询/创建 |
| PATCH | `/api/v1/skills/:id` | 编辑或停用 |
| GET/POST | `/api/v1/positions` | 岗位查询/创建 |
| GET/PATCH | `/api/v1/positions/:id` | 岗位详情/修订 |
| GET/POST | `/api/v1/employees` | 员工列表/创建草稿 |
| GET/PATCH | `/api/v1/employees/:id` | 详情/非状态字段更新 |
| POST | `/api/v1/employees/:id/materialize` | 生成 promptSnapshot/session |
| POST | `/api/v1/employees/:id/onboarding-check` | 入职检查 |
| POST | `/api/v1/employees/:id/suspend|resume|offboard` | 生命周期动作 |

硅基员工创建必须提交 `primaryPositionId/connectionProfileId/name`；服务端生成 employeeNo、sessionKey 和 promptSnapshot，不接受客户端指定可信 sessionKey。

### 2.3 Permission

`POST /permission-requests`、`POST /:id/approve`、`reject`、`revoke`；审批请求必须带 reason 和 expiresAt。查询有效权限返回基线、增量和来源，不只返回扁平集合。

### 2.4 Flow / Project / Work

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET/POST | `/api/v1/flows` | 流程定义 |
| POST | `/api/v1/flows/:id/versions` | 从草稿创建版本 |
| POST | `/api/v1/flows/:id/versions/:version/validate` | 发布前校验 |
| POST | `/api/v1/flows/:id/versions/:version/publish` | 发布不可变版本 |
| GET/POST | `/api/v1/projects` | 项目列表/创建 |
| POST | `/api/v1/projects/:id/start` | 快照版本并生成实例/工作项 |
| GET | `/api/v1/projects/:id/runtime` | 项目运行只读模型 |
| GET/POST | `/api/v1/work-items` | 工作项列表/自由模式创建 |
| PATCH | `/api/v1/work-items/:id` | 受状态机约束的更新 |

### 2.5 Dispatch / Evidence

| 方法 | 路径 | 关键规则 |
| --- | --- | --- |
| POST | `/api/v1/work-items/:id/dispatch/preview` | 只计算候选，不占容量 |
| POST | `/api/v1/dispatches/:id/confirm` | 幂等、占容量、启动执行 |
| POST | `/api/v1/dispatches/:id/cancel` | 受当前状态约束 |
| GET | `/api/v1/dispatches` | 按状态/项目/员工筛选 |
| POST | `/api/v1/executions/:id/receipts` | Connector/同步器提交结构化回执 |
| GET | `/api/v1/work-items/:id/receipts` | 证据历史 |
| POST | `/api/v1/receipts/:id/acceptances` | 通过、驳回、返工 |

派发预览返回：`dispatchId/workItemSnapshot/candidates[]/selectedEmployeeId/recommendationReason/riskSummary/expiresAt`。不可选候选保留 `ineligibleReasons[]` 供解释，但不得被确认。

## 3. Connector 合同

```ts
interface Connector {
  inspect(): Promise<ConnectorInspection>
  testManageability(profile: ConnectionProfile): Promise<ManageabilityResult>
  createSession(input: CreateSessionInput): Promise<RuntimeBinding>
  dispatch(envelope: DispatchEnvelope): Promise<ExecutionHandle>
  cancel(handle: ExecutionHandle): Promise<CancelResult>
  collectReceipts(cursor?: string): Promise<ReceiptBatch>
}
```

每个 Connector 必须声明 capabilities；不支持的能力明确返回 `unsupported`，不得假装成功。命令、endpoint 和输出必须经过 schema 与长度限制。Connector 错误统一映射为稳定错误码。

## 4. 数据表最小集合

`schema_migrations, adapter_templates, connection_profiles, health_checks, skills, positions, position_skills, position_permissions, employees, runtime_bindings, permission_requests, flow_definitions, flow_versions, flow_nodes, flow_edges, position_slots, projects, flow_instances, node_instances, work_items, work_item_dependencies, dispatches, candidate_scores, capacity_leases, executions, receipts, deliverables, acceptances, audit_events`。

所有业务表具有 `id/created_at/updated_at/version`；软删除对象增加 `status` 或 `deleted_at`。证据和审计表追加写，不提供普通删除 API。

## 6. 后端完成定义

- OpenAPI/Schema 与实现一致，合同测试通过。
- 领域规则有单元测试，路由有集成测试，Connector 有合同测试。
- 迁移、并发、取消、重试和异常恢复均有负面用例。
- 不改变合同即可由前端 mock 切换到真实 API。
- 每个任务提交 schema 变化、迁移影响、测试结果和未关闭风险。

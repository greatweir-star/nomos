## 3. 关键路径

```text
ARCH/API/DB 基线
→ ConnectionProfile
→ Position + Employee + RuntimeBinding
→ FlowVersion + ProjectSnapshot + WorkItem
→ Candidate + Dispatch + Execution
→ Receipt + Acceptance
→ Dashboard + Migration + Release
```

前端不等待后端完整实现：每个 Sprint 首日冻结对应 schema，前端使用 mock server，后端通过合同测试，迭代中点开始真实联调。

## 5. 联调合同

- 每个领域在 Sprint 开始前提交 schema、mock、错误码和状态枚举。
- 前端不得依赖未进入合同的字段；后端不得静默改变枚举语义。
- 合同变化需产品、架构、前端、后端、测试共同确认。
- 联调缺陷当天分流：合同问题归架构，业务歧义归产品，实现问题归对应开发。

## 6. 风险登记

| 风险 | 概率/影响 | 预防 | 触发后的处理 |
| --- | --- | --- | --- |
| SQLite 原生依赖打包失败 | 中/高 | Sprint 1 完成 macOS/Windows Spike | 在同一 repository 接口下切换备选驱动 |
| CLI 版本差异导致 Connector 不稳定 | 高/高 | 能力声明、合同测试、稳定错误码 | 降级为不可管理，不阻断其他连接 |
| React 迁移范围失控 | 中/高 | 按页面 strangler，禁止大爆炸 | 保留旧入口，缩回未完成页面 |
| 旧数据映射歧义 | 高/高 | dry-run 和人工复核表 | 不自动创建员工，允许跳过并保留旧库 |
| 前后端合同漂移 | 中/高 | schema-first、mock 和合同测试 | 冻结接口，变更走 ADR/变更单 |
| 智能体并行修改冲突 | 中/中 | 按 feature/模块分配文件所有权 | 项目经理重新切片，禁止互相覆盖 |
| 范围被华为流程/远程能力扩大 | 高/高 | 非范围清单和变更门禁 | 移入后续版本，不进入当前 Sprint |

## 7. 状态和汇报规则

- `Ready`：输入、依赖、验收、文件范围齐全。
- `In Progress`：负责人已领取，预计完成时间明确。
- `Review`：实现和自测完成，等待角色评审。
- `Blocked`：阻塞原因、所需决策和影响已记录。
- `Done`：满足版本完成定义并附证据。

每个智能体回报必须包含：已完成、修改文件、测试结果、风险/未做、需要决策、建议下一步。

## 8. 迭代门禁

- 迭代开始：范围、schema、用例和依赖 Ready。
- 迭代中点：前后端至少完成一次真实合同联调。
- 迭代结束：演示纵向业务结果；P0/P1 缺陷关闭；文档同步。
- 未达到出口的工作不得以“代码已写”结转为完成，必须重新估算和拆分。

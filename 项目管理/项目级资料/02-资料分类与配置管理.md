# 资料分类与配置管理

> 目标：在不破坏历史链接的前提下，将全部现有资料纳入项目级或版本级管理。

## 1. 分类规则

### 项目级资料

长期跨版本有效，回答“Nomos 为什么做、如何管理、共同规则是什么”。包括：

- 根目录项目说明、项目图谱和长期产品说明。
- `产品规划/00-产品理念`、`01-调研资料`。
- 产品开发方法论、模板和通用测试规范。
- 商业化总纲、长期实施路径和通用交付协议。
- 参考源码与外部方法论研究。

### 版本级资料

带有明确版本、阶段或发布目标，回答“这个版本具体做什么、怎么做、如何验收”。包括：

- `产品规划/02-PRD`、`03-版本规划`、`04-详细规划`。
- `openspec/changes/*`。
- `产品开发/PROGRESS.md`、版本测试用例和测试报告。
- `产品开发/nomos-desktop/docs` 中的 PRD、架构和开发计划。
- `产品发布/v*` 及发布说明。
- 当前版本的产品、架构、前端、后端、测试、计划和验收材料。

## 3. 命名与版本规则

- 版本统一写作 `V0.0.3`，目录使用 `V0.0.3`。
- PRD 文档版本 `0.3 Draft` 是需求文档修订号；产品交付版本统一映射为 `V0.0.3`。
- 每个版本必须包含：入口、PRD、架构、前端、后端、测试、计划、验收、交接。
- 发布后版本目录只允许勘误；功能变化必须建立新版本。

## 4. 基线与追踪

- 需求 ID 沿用核心 PRD 的 `DASH/EMP/POS/CAP/FLOW/DSP/PRJ/SET-*`。
- 工程任务使用 `PM/ARCH/FE/BE/QA-*`。
- 测试用例使用 `TC-领域-序号`。
- 缺陷使用 `BUG-V003-序号`。
- ADR 使用 `ADR-V003-序号`。
- 提交材料必须引用至少一个需求 ID；测试必须引用需求 ID 和任务 ID。

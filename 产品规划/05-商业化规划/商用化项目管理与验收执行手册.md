# Nomos 商用化项目管理与验收执行手册

> 状态：Draft
> 日期：2026-06-12
> 用途：作为产品经理和项目经理管理 Nomos 商用化开发、验收、发布和客户试点的执行手册。

## 0. 管理目标

商用化阶段的管理目标不是“让智能体多写代码”，而是让每个智能体交付的增量都能进入真实客户试点。项目经理要控制四件事：

1. 范围不漂移。
2. 质量不失控。
3. 数据不丢失。
4. 客户可交付。

## 1. 项目阶段

| 阶段 | 管理目标 | 退出条件 |
|------|----------|----------|
| C0 商用加固 | 恢复并稳定 v1.2 基线 | P0 测试全绿，核心接口可用 |
| C1 Local Pilot | 支持设计伙伴试点 | License、向导、支持包、样例工作区可用 |
| C2 工作项试点 | 支持真实流程执行颗粒 | 工作项和事件账本可用 |
| C3 Agent 治理 | 支持受控 Agent 派发 | 派发、回执、幂等、复核可用 |
| C4 Pro GA | 支持单机付费交付 | 资源成本、模板治理、知识复盘齐备 |
| C5 Workflow Beta | 支持可运行 Workflow | L2-L5、节点、事件回放可用 |
| C6 Team Beta | 支持小团队协作 | 工作区、成员、同步、冲突处理可用 |
| C7 Enterprise | 支持企业采购 | RBAC、SSO、私有部署、安全材料齐备 |

## 2. 节奏

### 2.1 每周节奏

| 时间 | 动作 | 输出 |
|------|------|------|
| 周一 | 确认本周任务包和验收门禁 | 周任务清单 |
| 周三 | 中期检查阻塞和范围漂移 | 风险清单 |
| 周五 | 验收、测试、文档和发布判断 | 周验收记录 |

### 2.2 每个任务节奏

```text
任务包 Ready
  -> 智能体开发
  -> 自测和回执
  -> 测试智能体验证
  -> PM 验收
  -> 合并/发布/返工
```

### 2.3 每个版本节奏

```text
版本目标
  -> 范围冻结
  -> 开发完成
  -> P0 门禁
  -> 发布候选
  -> 客户试点
  -> 复盘和下一版 Backlog
```

## 3. RACI

| 工作 | PM | 架构智能体 | 后端智能体 | 前端智能体 | 测试智能体 | 安全智能体 | 发布智能体 |
|------|----|------------|------------|------------|------------|------------|------------|
| 需求定义 | A/R | C | C | C | C | C | C |
| 技术方案 | A | R | C | C | C | C | C |
| 开发实现 | A | C | R | R | C | C | C |
| 自动化测试 | A | C | C | C | R | C | C |
| 安全检查 | A | C | C | C | C | R | C |
| 验收签收 | A/R | C | C | C | C | C | C |
| 发布归档 | A | C | C | C | C | C | R |

说明：A = Accountable，R = Responsible，C = Consulted。

## 4. 任务进入开发门禁

任务进入 `Ready` 前必须满足：

- 有任务 ID。
- 有关联 PRD 或规划文档。
- 有明确做/不做范围。
- 有目标文件或模块范围。
- 有数据迁移要求。
- 有 API 或 UI 验收标准。
- 有测试要求。
- 有回退或失败处理说明。

不满足以上条件，任务保持 `Draft`。

## 5. 验收门禁

### 5.1 P0 门禁

以下任何一项失败，不允许进入客户试点：

- `npm test` 失败。
- 核心接口返回 500。
- 备份恢复失败。
- 数据迁移缺保护备份。
- 支持包泄露敏感信息。
- Agent 写入绕过二次确认。
- License 过期后阻止数据导出。
- 发布说明缺回退方式。

### 5.2 P1 门禁

以下问题允许进入设计伙伴试点，但必须记录风险和补救计划：

- 部分低频 UI 空态不完整。
- 支持包内容不足以定位所有问题。
- 样例数据不覆盖全部行业场景。
- 自动更新未完成，采用手工更新。

### 5.3 P2 门禁

P2 不阻断试点，但需要进入后续 Backlog：

- 企业 SSO。
- 私有更新源。
- 高级 RBAC。
- 模板市场。
- 多设备云同步。

## 6. C0 验收计划

### 6.1 验收目标

确认 v1.2.1-pilot 具备进入 Local Pilot 开发的稳定基线。

### 6.2 自动化验收

| 用例 | 标准 |
|------|------|
| `npm test` | 全部通过 |
| smoke tests | health/workspace/projects/org/flow/backup 通过 |
| migration tests | v6/v7/v8 样本迁移通过 |
| security tests | Host/Origin、路径穿越、确认令牌脱敏通过 |

### 6.3 手工验收

1. 新建空数据目录启动。
2. 打开工作区，确认没有演示项目。
3. 创建项目。
4. 初始化默认组织模板。
5. 创建流程模板。
6. 绑定流程到项目。
7. 创建备份。
8. inspect 备份。
9. restore 备份。
10. 查看 diagnostics。

## 7. C1 验收计划

### 7.1 验收目标

确认 Local Pilot 试点包可以被设计伙伴客户使用。

### 7.2 自动化验收

| 用例 | 标准 |
|------|------|
| license tests | trial/active/expired/invalid/missing 通过 |
| settings tests | GET/PATCH 和通道校验通过 |
| support tests | 支持包生成和脱敏扫描通过 |
| onboarding tests | 首次启动、跳过、样例初始化幂等通过 |

### 7.3 手工验收

1. 空数据启动，出现首次启动向导。
2. 选择 OPC 项目交付场景。
3. 确认初始化默认组织、流程和样例项目。
4. 导入试用 License。
5. 查看 License 状态。
6. 修改工作区名称。
7. 导出支持包。
8. 扫描支持包，确认无敏感信息。
9. 创建第一个真实项目。
10. 关闭并重启应用，确认状态保留。

## 9. 发布判断

### 9.1 可以进入 pilot 的条件

- C0 P0 全部通过。
- C1 核心链路通过。
- 已知 P1 有记录和绕行方案。
- 用户手册和试点手册齐备。
- 支持包可导出且脱敏。
- 有回退包或回退步骤。

### 9.2 可以进入 stable 的条件

- pilot 至少完成 1 个设计伙伴试点。
- P0/P1 全部关闭。
- 试点复盘显示产品价值成立。
- 安装、升级、备份、恢复、支持流程可由客户自行完成。

### 9.3 不允许发布的条件

- 自动化测试失败。
- 有 S0/S1 未关闭。
- 数据迁移无法回退。
- 支持包泄露敏感信息。
- 发布说明缺少已知问题和回退方案。

## 10. 客户试点管理

### 10.1 试点启动材料

- 试点目标。
- 客户联系人。
- 试点流程或项目。
- 预计结束日期。
- 成功指标。
- 支持响应方式。
- 数据和隐私说明。

### 10.2 试点复盘材料

| 项 | 内容 |
|----|------|
| 目标完成 | 是否完成试点项目或流程 |
| 价值证据 | 节省时间、减少返工、Agent 贡献、流程透明度 |
| 主要问题 | 产品问题、数据问题、流程问题、组织问题 |
| 续费建议 | 继续 Pilot、升级 Pro、暂停、转 Enterprise |
| 下一步 | 任务清单和负责人 |

## 11. 文档同步要求

任何代码开发完成后，必须同步更新：

- PRD 或详细设计。
- 用户手册。
- 测试报告。
- 发布说明。
- 商用化验收矩阵。
- 若涉及智能体任务，则更新任务拆解或协作协议。

文档未更新，不进入 `Accepted`。

## 12. 项目经理日常检查清单

每天检查：

- 当前任务是否都有 ID 和验收标准。
- 是否有 P0 阻塞。
- 是否出现范围漂移。
- 是否有未同步文档的代码变更。
- 是否有测试失败但无人负责。
- 是否有客户数据或敏感信息风险。

每周检查：

- C0/C1 门禁完成率。
- 缺陷关闭率。
- 文档完备率。
- 发布候选状态。
- 试点客户反馈。

# Nomos 商用就绪验收矩阵

> 状态：Draft
> 日期：2026-06-11
> 用途：作为 Nomos 从内部版本、设计伙伴试点、付费 Pro、Team Beta 到 Enterprise 的发布门禁。

## 0. 验收分级

| 优先级 | 含义 | 处理原则 |
|--------|------|----------|
| P0 | 不满足则不得给客户交付 | 必须在发布前关闭 |
| P1 | 不满足会显著影响试点/续费 | 可带明确风险进入设计伙伴试点，GA 前关闭 |
| P2 | 增强体验或企业采购加分项 | 可进入后续版本 |

## 1. 发布通道定义

| 通道 | 可面向对象 | 进入条件 |
|------|------------|----------|
| internal | 内部开发和演示 | 核心链路可跑，允许已知缺陷 |
| pilot | 设计伙伴和陪跑试点 | P0 全关，P1 有风险记录和回退方案 |
| stable | 标准付费客户 | P0/P1 全关，文档、支持和升级路径齐备 |
| enterprise | 企业/私有化客户 | stable 条件 + 企业安全、权限、审计和部署材料 |

## 2. P0 商用门禁

| 域 | 验收项 | 当前基线判断 | 验收方法 |
|----|--------|--------------|----------|
| 启动 | 空数据目录首次启动成功，不写入演示项目 | 已有测试覆盖方向 | 新建临时数据目录启动服务，检查项目为空 |
| 接口 | `/api/health`、`/api/workspace`、项目、组织、流程、备份接口全部可用 | 需要 C0 检查路由导入和参数 | 自动冒烟测试 + 手工浏览器验证 |
| 测试 | `npm test` 全部通过 | 必须保持 | CI/本地测试报告 |
| 数据迁移 | v6/v7/v8 数据可迁移到当前版本 | 已有基础迁移 | 迁移样本测试 |
| 备份恢复 | 创建备份、查看备份、恢复备份、恢复前保护备份闭环 | 已有基础能力 | 自动测试 + 手工演练 |
| 数据保护 | 损坏数据文件不会覆盖原文件 | 已有 `.invalid-*` 机制 | 注入损坏 JSON 测试 |
| 本机访问 | HTTP 服务只允许 loopback 和可信 Origin | 已有基础能力 | Host/Origin 负面测试 |
| 高风险确认 | 删除、恢复、执行、写入任务必须显式确认 | 已有基础能力 | API 负面测试 |
| Agent 执行 | 默认只读，写入二次确认，确认令牌不返回持久化明文 | 已有基础能力 | 执行预览/确认测试 |
| 敏感信息 | 支持包、审计、回执、Agent 信封不得包含 Token/API Key | 需补诊断包后验证 | Secret fixture 扫描 |
| 发布包 | 安装包/便携包可在干净机器启动 | 需补 C0 发布验收 | Windows 干净环境验收 |
| 发布说明 | 每个客户版本有版本号、范围、已知问题、回退方式 | 已有 release notes 基础 | 发布清单检查 |
| 用户数据出口 | 客户可导出数据和备份，不被 License 锁死 | 需补 License 后验证 | 过期 License 场景测试 |
| 错误可支持 | 关键失败有可读错误和诊断信息 | 需补错误码/诊断包 | 故障注入测试 |

## 5. 手工验收路径

### 路径 A：Local Pilot

1. 在干净机器上安装或解压 Nomos。
2. 首次启动，选择 Local Pilot，设置数据目录。
3. 导入或生成试用 License。
4. 初始化默认组织和流程模板。
5. 创建一个项目，绑定 `项目交付` 或 `LTC 轻量版` 流程。
6. 添加项目资料和阶段交付物。
7. 推进到需要 Agent 的阶段，生成派发预览。
8. 以只读模式派发本地 Agent。
9. 回收结构化回执，进入人工验收。
10. 创建备份，关闭应用，重新打开，检查数据保留。
11. 恢复备份，确认保护备份存在。
12. 导出诊断包，检查不含敏感令牌。

### 路径 B：Pro

1. 导入 Pro License。
2. 创建流程模板和流程实例。
3. 拆解工作项，设置依赖、负责人、Skill、截止时间。
4. 观察进度看板和资源看板。
5. 对工作项发起 Agent 派发，取消一次、重试一次、成功一次。
6. 录入成本、产能和复盘。
7. 将流程模板从 draft 提升到 active。
8. 生成 v2.0 准备度报告。
9. 导出客户价值复盘报告。

### 路径 C：Workflow Beta

1. 选择一条 v1.6 active 流程模板。
2. 运行 v2.0 升级预检。
3. 创建保护备份。
4. 迁移为 L2-L5 Workflow 模板。
5. 启动 Workflow 实例。
6. 执行碳节点、硅节点、碳硅节点。
7. 触发关口、返工、分支。
8. 回放事件流，确认状态可重建。
9. 回退到迁移前备份，确认旧流程仍可打开。

| 测试包 | 覆盖内容 |
|--------|----------|
| smoke.test.js | health、workspace、项目、组织、流程、备份、诊断 |

## 7. 发布清单

每次进入 `pilot`、`stable` 或 `enterprise` 通道前，必须产出：

- 安装包或便携包。
- SHA256 校验值。
- 发布说明。
- 回退包或回退步骤。
- 数据迁移说明。
- 测试报告。
- 已知问题清单。
- 用户手册更新。
- 管理员/实施手册更新。
- 支持响应说明。
- 第三方许可证和模型风险说明。

## 8. 一票否决项

出现以下任一情况，不得交付客户：

- 空数据启动失败或污染客户工作区。
- 数据迁移不可逆且没有保护备份。
- 备份恢复失败。
- 高风险操作无需确认即可执行。
- Agent 写入任务绕过二次确认。
- 诊断包或审计中泄露 Token/API Key。
- 安装包无法在干净机器启动。
- License 过期后阻止客户导出自己的数据。
- 发布说明缺失回退方式。
- `npm test` 或 P0 冒烟测试失败。

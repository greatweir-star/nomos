# Nomos 商用化实施路径

> 状态：Draft
> 日期：2026-06-11
> 范围：把商用化能力从规划拆成可执行里程碑、工程任务、交付材料和验收门槛。

## 0. 路线原则

Nomos 商用化不应等待 v2.0 全部完成。更稳妥的路径是：

1. 先把 v1.2 本地优先能力加固成可陪跑试点版本。
2. 用 v1.3-v1.6 补真实执行数据，让客户能把流程跑起来。
3. 在 v2.0 上升级 Workflow 引擎，把执行经验变成可调度系统。
4. 同步补授权、安装、支持、数据安全和发布治理，让产品可以收费、交付和续费。

## 1. 并行工作流

| 工作流 | 目标 | 主要负责人 | 关键产物 |
|--------|------|------------|----------|
| Product Core | 完成工作项、派发、资源成本、知识治理、Workflow 引擎 | 产品 + 应用工程 | PRD、详细设计、API、UI、测试 |
| Commercial Control | 让产品可授权、可分版、可更新、可续费 | 产品 + 后端/桌面工程 | License、版本通道、套餐开关、更新策略 |
| Trust & Data | 让客户数据安全、可备份、可迁移、可审计 | 后端 + 安全 + QA | 数据迁移、加密、审计、导入导出、回退 |
| Delivery & Success | 让客户能完成试点、培训、诊断和价值复盘 | 产品 + 客户成功 | 试点手册、模板包、培训材料、诊断包 |
| Quality & Release | 让每个版本可验证、可回滚、可追责 | QA + 发布负责人 | 测试矩阵、发布清单、签名包、回归报告 |

## 3. C0：商用加固

### 目标

把当前 v1.2.0 从“开发可跑”加固到“可给设计伙伴试点”。此阶段不扩大业务范围，只修稳定性、安全和发布问题。

### 工程任务

- 修复路由拆分后的接口依赖问题，确保 `/api/workspace`、`/api/agents`、`/api/adapters`、`/api/flow-*` 全部可用。
- 补齐 `npm test` 覆盖的所有接口导入和参数传递问题。
- 增加 API 冒烟测试：健康检查、工作区、项目、组织、流程、备份、执行预览。
- 对 `nomos-data.json` 增加启动时完整性校验和异常恢复提示。
- 增加诊断包导出：数据版本、系统信息、最近审计、最近错误、Agent 状态，不包含敏感令牌。
- 明确数据目录、备份目录和日志目录。
- 生成 v1.2.1 发布说明和回退包。

### 验收标准

- `npm test` 全部通过。
- 新建空数据目录启动后无 demo 项目污染。
- 旧 v6/v7/v8 数据可迁移，失败时保留 `.invalid-*` 文件。
- 备份、inspect、restore 可闭环，恢复前创建保护备份。
- 本地 HTTP 服务只接受 localhost/127.0.0.1 和同源请求。
- 所有写入、删除、执行和恢复类高风险操作有审计记录。

## 4. C1：Local Pilot 试点包

### 目标

让 Nomos 能被真实客户安装、试用、授权并进入陪跑试点。

### 产品任务

- 首次启动向导：选择使用场景、数据目录、是否初始化默认组织/流程模板。
- 示例工作区：OPC 项目交付、LTC 轻量流程、数字员工草稿 3 个样例。
- 试点目标面板：本次试点要完成的流程、项目、验收指标和客户负责人。
- 用户手册补充：安装、授权、备份、恢复、Agent 连接、数据导出。
- 试点复盘模板：试点目标、完成情况、风险、续费建议。

### 商业任务

- License 文件格式：客户名、版本、套餐、有效期、设备限制、功能开关、签名。
- 本地激活页：导入 License、显示试用/正式/过期状态。
- 试用策略：默认 14 天或 30 天，可由 License 延长。
- 版本通道：internal、pilot、stable 三类。
- 许可范围文案：本地数据、本地 Agent 风险、第三方模型和 CLI 依赖。

### 技术任务

- 新增数据模型：`license`、`settings`、`supportBundles`。
- 新增接口：`GET /api/license`、`POST /api/license/import`、`GET /api/support/bundle`、`GET /api/settings`、`PATCH /api/settings`。
- License 验签先支持离线公钥校验；在线激活后置。
- 功能开关只用于商业能力，不阻断客户访问自己的已有数据。

### 验收标准

- 无 License 时可进入试用；过期后只限制新增高价值能力，不锁死客户数据导出。
- 导入无效 License 必须给出可读错误，不破坏本地数据。
- 支持包导出不包含确认令牌、API Key、MCP Token、用户私密路径全文。
- 试点用户能在 30 分钟内完成安装、初始化和第一个项目创建。

## 5. C2：工作项试点

### 目标

落地 v1.3：把流程阶段拆成可执行、可分配、可验收、可追踪的工作项。

### 依赖文档

- `产品规划/02-PRD/PRD_V1_3_WORK_ITEMS_AND_DASHBOARDS.md`
- `产品规划/03-版本规划/ROADMAP_V1_3_PLUS.md`
- `产品规划/03-版本规划/ACCEPTANCE_MATRIX_V1_3_TO_V2.md`

### 工程任务

- 数据迁移 v8 -> v9：新增 `workItems[]`、`workItemEvents[]`。
- 工作项 CRUD、状态机、负责人、角色、Skill、优先级、截止时间、验收标准。
- 工作项依赖和循环检测。
- 阶段、流程实例、项目详情和看板聚合。
- 旧 `workflowTasks[]` 镜像为工作项视图，保持五阶段项目兼容。

### 商用补充

- 工作项导入导出 CSV/JSON。
- 工作项审计和变更历史。
- 试点指标：计划工作项数、完成率、阻塞率、逾期率、返工次数。

### 验收标准

- 工作项写操作必须写入事件账本。
- 依赖未满足时不得进入 `in_progress`。
- 看板空数据返回空数组/0，不返回 null。
- 迁移前后项目数、流程实例数和可恢复备份数一致。

## 6. C3：Agent 治理试点

### 目标

落地 v1.4：让 Agent 任务从“可以调用”升级为“可以被客户信任地派发、复核和追责”。

### 工程任务

- 数据迁移 v9 -> v10：新增 `dispatchPolicies[]`、`agentDispatches[]`、`agentHealth[]`。
- 任务信封 v2：包含项目、流程、阶段、工作项、输入、验收标准、Skill、幂等键。
- 派发预览、显式确认、取消、重试、迟到回执处理。
- Agent 推荐：岗位、Skill、阶段、Adapter、健康状态。
- 多 Agent 协作记录：主执行、复核、交接、仲裁。

### 商用补充

- Agent 风险等级：只读、写入、外部网络、敏感数据、费用消耗。
- Agent 成本基础字段：模型、token、执行时长、外部服务费。
- 客户可配置策略：哪些 Agent 可用于哪些流程、哪些操作必须人工复核。

### 验收标准

- 未确认派发不得执行。
- 同一幂等键不得产生多个进行中派发。
- 取消后的迟到回执不得覆盖当前工作项状态。
- 敏感字段不得进入 Agent 信封和诊断包。
- 本地执行失败时工作项进入可解释状态，而不是静默失败。

## 7. C4：Pro GA

### 目标

把 v1.5-v1.6 和商用控制面合并成可收费的单机 Pro 版本。

### 工程任务

- 数据迁移 v10 -> v11：资源、产能、成本、组合看板。
- 数据迁移 v11 -> v12：决策记录、知识资产、复盘、模板版本、治理检查。
- License 套餐开关：Pilot、Pro、Team Preview。
- 自动或半自动更新检查：先提示下载，不做静默更新。
- 支持包和错误码稳定化。

### 产品任务

- Pro 首屏：项目健康、流程执行、Agent 待处理、资源成本、知识沉淀。
- 模板治理：baseline、draft、active、deprecated。
- v2.0 准备度报告。
- 客户价值复盘报告：节省时间、返工减少、Agent 贡献、流程瓶颈。

### 验收标准

- 一个客户可以在无开发者陪同下完成安装、授权、创建项目、绑定流程、拆工作项、派发 Agent、复盘模板。
- 数据导出和备份恢复可作为客户离场保障。
- 版本升级失败可回退到升级前备份。
- 用户手册、管理员手册、试点交付手册和发布说明齐备。

## 8. C5：Workflow Beta

### 目标

落地 v2.0：把 v1.x 沉淀的数据升级为可运行 Workflow 引擎。

### 工程任务

- 数据迁移 v12 -> v13：Workflow 模板、实例、节点、事件和运行记录。
- L2-L5 分层：阶段、任务、步骤、节点。
- 事件 reducer：状态可回放、可解释。
- 节点调度：碳、硅、碳硅节点不同策略。
- 关口、分支、返工和依赖。
- 兼容 v1.x 流程实例和工作项。

### 商用补充

- Workflow Beta 只对 Pilot/Pro 客户灰度开启。
- 引擎迁移必须先生成预检报告和保护备份。
- 运行中实例默认不自动升级。

### 验收标准

- 一个 4 阶段/12 节点 Workflow 可完整运行和回放。
- 硅节点可经 v1.4 派发链路执行并回收结构化结果。
- 关口节点可根据准入准出标准进入人工/Agent 评审。
- reducer 测试、迁移测试、回退测试、性能测试全部通过。

## 9. C6：Team Beta

### 目标

从单机商用进入小团队协作。

### 工程任务

- 账号体系：邮箱/密码或第三方登录。
- 工作区和成员：Owner、Admin、Member、Viewer。
- 云同步：项目、流程、组织、模板、工作项、事件账本。
- 冲突解决：本地优先、服务端版本、人工合并。
- 团队审计：成员操作、设备、同步状态。

### 商用补充

- 席位计费。
- 团队套餐。
- 在线激活和续费。
- 支持工单和客户组织 ID。

### 验收标准

- 两台设备可在同一工作区看到一致的项目和流程状态。
- 离线编辑后重新联网可合并，不丢失本地变更。
- 成员退出团队后无法继续同步新数据，但仍可导出自己的本地副本。

## 10. C7：Enterprise

### 目标

满足企业采购、私有化部署和安全审查。

### 工程任务

- SSO：OIDC/SAML。
- RBAC：工作区、项目、流程、模板、Agent、数据导出分级权限。
- 私有部署：客户自有云/内网部署，私有更新源。
- 审计保留：可配置保留期限、导出格式和签名校验。
- 企业模型网关：统一管理模型、Key、额度、审计。
- 企业集成：Webhook、Open API、SCIM、数据仓库导出。

### 交付任务

- 安全白皮书。
- 部署手册。
- 运维手册。
- SLA 和支持流程。
- 第三方依赖和开源许可证清单。

### 验收标准

- 企业安全评审能获得系统架构、数据流、权限、审计、备份、模型调用和第三方依赖说明。
- 私有部署环境可完成安装、升级、回退和灾备演练。
- 关键审计事件可追踪到人、时间、对象和变更内容。

## 13. 风险与控制

| 风险 | 表现 | 控制方式 |
|------|------|----------|
| 产品核心未稳定就卖 | 客户数据或流程中断 | C0 硬门禁，不通过不试点 |
| Agent 权限过大 | 本地文件或敏感数据被误用 | 显式授权、只读默认、写入二次确认、风险等级 |
| JSON 单文件增长 | 大客户数据量下性能下降 | 指标阈值、归档策略、后续 SQLite/服务端存储评估 |
| 版本迁移失败 | 客户升级后无法打开数据 | 预检、保护备份、迁移回退、迁移测试集 |
| 商业外壳过早复杂 | 拖慢核心价值验证 | C1 先离线 License，在线计费后置 |
| 企业需求发散 | 变成通用 BPM 或 OA | 坚持组织 + 流程 + Agent + Workflow 主线 |

## 14. 每个版本必须产出的材料

- PRD 或详细设计。
- 数据迁移说明。
- API 变更说明。
- 测试用例和测试报告。
- 发布说明。
- 用户手册更新。
- 管理员/实施说明更新。
- 已知问题和回退方案。

缺少以上任一材料，不进入稳定或客户交付通道。

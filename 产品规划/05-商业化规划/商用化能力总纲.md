# Nomos 商用化能力总纲

> 状态：Draft
> 日期：2026-06-11
> 范围：在现有 v1.2 本地优先桌面端、v1.3-v1.6 执行数据坡道和 v2.0 Workflow 引擎规划之上，补齐 Nomos 从“可用产品”到“可销售、可交付、可运维、可续费产品”的横向能力。

## 0. 文档定位

现有规划已经清楚描述了 Nomos 的产品核心：组织、流程、工作项、Agent 派发、资源成本、知识治理和 Workflow 引擎。本文件不替代这些版本规划，而是补齐商用化所需的横向能力面。

商用化目标不是“多做几个功能”，而是让客户可以真实购买、安装、授权、导入数据、稳定使用、出现问题能被支持、版本能安全升级、合同能续费。

## 1. 当前基线

截至 v1.2.0，Nomos 已具备以下产品基础：

| 能力 | 当前状态 | 商用化判断 |
|------|----------|------------|
| 本地优先桌面端 | 已有 Electron Windows x64 便携版 | 可作为 Local-first 版本基座 |
| 本机 HTTP 后端 | 已有 loopback 限制和 Origin 校验 | 需要补应用级会话令牌和安全基线测试 |
| JSON 持久化 | 已有 `nomos-data.json`、迁移、备份、恢复 | 需要补数据完整性校验、导入导出、加密和大数据容量策略 |
| 项目五阶段链路 | 已有项目、阶段、验收、返工、交付物 | 可支撑早期项目交付场景 |
| 组织管理 | 已有 Skill、岗位、员工、Adapter、组织健康度 | 需要补 RBAC、岗位权限和客户初始化模板 |
| 流程管理 | 已有流程模板、实例、阶段、关口评审 | 需要补工作项、模板版本和治理 |
| Agent 路由和本地执行 | 已有 Alice/Codex CLI/Claude Code/OpenClaw 接入思路 | 需要补 Agent 风险等级、执行隔离、凭证治理和用量成本 |
| 发布工程 | 已有 `electron-builder` portable 打包 | 需要补签名、安装器、更新通道、发布回滚和许可证 |
| 测试 | 已有 Node 集成测试 | 需要补冒烟、回归、安全、迁移、性能和安装包验收 |

结论：Nomos 已经有“产品内核”，但还不是完整商用品。商用化优先补的是商业控制面、数据安全面、交付运维面和质量门禁。

## 2. 商用定义

Nomos 达到商用，需要满足 6 条最低定义：

1. 客户能获得明确版本：安装包、版本号、更新说明、许可条款、支持范围一致。
2. 客户能安全试用和购买：试用授权、正式授权、离线授权、续费和过期策略可解释。
3. 客户能导入自己的组织和流程：模板、样例、初始化向导、导入导出和备份恢复可用。
4. 客户数据可控：本地数据位置透明、敏感数据可脱敏、备份可验证、升级可回退。
5. 故障可支持：诊断包、日志、错误码、操作审计和支持流程齐备。
6. 版本可持续：自动化测试、发布门禁、迁移策略、签名更新和客户沟通机制稳定。

## 3. 目标客户和交付形态

| 客户类型 | 典型诉求 | 推荐交付形态 | 首个可售卖价值 |
|----------|----------|--------------|----------------|
| OPC / 小型工作室 | 用 Agent 管项目交付，避免任务失控 | Local Pilot / Pro 单机版 | 项目指挥台、Agent 派发、验收回执 |
| 中小企业管理团队 | 建模组织和关键流程，让执行透明 | Pro 单机版 + 咨询交付包 | 组织建模、流程模板、工作项看板、复盘 |
| 数字员工试点团队 | 将岗位、Skill、Agent 和流程打通 | Pro / Team Beta | 数字员工上岗流程和受控派发 |
| 企业客户 / 私有化客户 | 数据本地化、权限、审计、集成 | Enterprise 私有化 | RBAC、审计、私有部署、集成接口 |

## 4. 产品分层

Nomos 商用架构分为 4 层：

| 层级 | 职责 | 主要能力 |
|------|------|----------|
| Core Runtime | 运行项目、组织、流程、工作项、Agent、Workflow | v1.2-v2.0 已规划的产品核心 |
| Commercial Control Plane | 管理账号、授权、版本、套餐、更新、支持状态 | 许可、激活、版本通道、支持包、客户标识 |
| Trust & Data Plane | 管理数据安全、备份、迁移、审计、合规和权限 | 加密、导入导出、RBAC、审计、隐私、回退 |
| Delivery & Success Plane | 管理客户落地、模板、培训、支持、续费和最佳实践 | 初始化向导、模板包、诊断包、客户成功 Playbook |

## 7. 首批可销售场景

### 场景 A：OPC Agent 项目指挥台

客户用 Nomos 管理一个真实交付项目，从目标拆解、PRD、开发、测试、预览发布到人工验收，所有 Agent 任务有信封、回执、审计和交付物。

最低成交能力：v1.2.1 加固 + Local Pilot 授权 + 用户手册 + 诊断包。

### 场景 B：中小企业流程落地包

客户将 LTC、项目交付或 IPD 轻量流程录入 Nomos，绑定岗位和 Skill，用工作项看板跟踪执行，用复盘沉淀模板。

最低成交能力：v1.3 工作项 + v1.6 模板治理 + 行业模板包。

### 场景 C：数字员工受控上岗

客户为一个岗位配置数字员工，经过岗位匹配、入职培训、师父带教、工具分配、沙盒实习和转正上岗，由 Nomos 控制派发与复核。

最低成交能力：v1.4 Agent 派发治理 + v2.1 数字员工六步生成。

## 8. 商用前不做

为了尽快形成可售卖闭环，以下能力不进入首个商用版本：

- 不做移动端 App。
- 不做公开模板市场。
- 不做完整财务账务和发票系统。
- 不做完全自主 Agent 运行，无人工确认的高风险操作继续禁止。
- 不做跨企业数据共享。
- 不做强监管行业专用合规认证。
- 不做通用低代码 BPM 替代品，Nomos 的核心仍是“组织 + 流程 + Agent + Workflow”。

## 9. 商用成熟度分级

| 等级 | 定义 | 发布判断 |
|------|------|----------|
| R0 内部可用 | 开发者能跑通核心链路 | 仅用于内部演示 |
| R1 设计伙伴试点 | 真实客户可在陪跑下完成 1 个项目或 1 条流程 | 可签试点合同 |
| R2 付费可交付 | 客户能自行安装、授权、备份、恢复、导出诊断包 | 可卖 Local Pilot / Pro |
| R3 标准化销售 | 有官网/报价/授权/更新/支持/培训/续费流程 | 可规模销售 |
| R4 企业交付 | 有私有化、SSO、RBAC、审计、合规和 SLA | 可进入企业采购 |

## 10. 与现有 Roadmap 的关系

```text
产品核心路线：
v1.2 -> v1.3 -> v1.4 -> v1.5 -> v1.6 -> v2.0 -> v2.1 -> v3.0

商用化路线：
C0 商用加固 -> C1 试点包 -> C2 工作项试点 -> C3 Agent 治理 -> C4 Pro GA -> C5 Workflow Beta -> C6 Team -> C7 Enterprise
```

两条路线并行推进。产品核心路线决定 Nomos “能做什么”，商用化路线决定 Nomos “能不能被客户放心购买和长期使用”。

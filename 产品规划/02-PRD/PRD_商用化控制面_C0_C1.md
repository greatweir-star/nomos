# PRD：商用化控制面 C0-C1

> 状态：Draft
> 日期：2026-06-12
> 版本范围：C0 商用加固、C1 Local Pilot 试点包
> 关联文档：`产品规划/05-商业化规划/商用化能力总纲.md`、`产品规划/05-商业化规划/商用化实施路径.md`、`产品规划/05-商业化规划/商用就绪验收矩阵.md`

## 1. 背景

Nomos v1.2.0 已经具备本地优先桌面端、项目链路、组织管理、流程管理、Agent 路由和本地执行等产品内核。但它目前还不能直接作为商用品交付给客户，主要原因是：

- 客户无法清楚完成安装、初始化、授权和试点目标配置。
- 产品没有正式的 License、版本通道、支持包和客户标识。
- 诊断、错误、备份、恢复、发布和回退仍是开发者视角。
- 当前测试暴露接口稳定性问题，必须先完成 C0 加固。

C0-C1 的目标是先形成可陪跑的 Local Pilot 试点包，不等待 v1.3-v2.0 全部完成。

## 2. 产品目标

### 2.1 C0 目标

把当前 v1.2.0 加固为 `v1.2.1-pilot` 候选版本，使设计伙伴可以在陪跑下完成一个真实项目或一条流程试点。

### 2.2 C1 目标

提供 Local Pilot 试点控制面，让客户可以完成：

1. 首次启动和场景初始化。
2. 导入或生成试用 License。
3. 查看当前套餐、有效期、版本通道和数据目录。
4. 导出支持包。
5. 使用样例组织、流程和项目开始试点。

## 3. 用户与场景

| 用户 | 诉求 | C0-C1 要支持的动作 |
|------|------|--------------------|
| 设计伙伴客户 | 快速开始试点，不被技术细节阻塞 | 安装、初始化、创建首个项目、导入 License |
| 客户管理员 | 知道数据在哪里，遇到问题能导出诊断 | 查看数据目录、备份、恢复、导出支持包 |
| Nomos 产品/项目经理 | 能验收客户是否达到试点目标 | 配置试点目标、查看系统状态、收集诊断 |
| 实施顾问 | 需要标准化交付和培训 | 使用样例数据、试点手册、复盘模板 |
| 开发智能体 | 需要清晰任务边界 | 按模块、接口、测试、验收条件执行 |

## 4. 成功指标

| 指标 | C0 门槛 | C1 门槛 |
|------|---------|---------|
| 本地测试 | `npm test` 全部通过 | 新增 license/support/settings/onboarding 测试通过 |
| 首次启动 | 空数据目录启动成功 | 30 分钟内完成初始化和首个项目创建 |
| 诊断支持 | 可查看系统诊断 | 可导出脱敏支持包 |
| 备份恢复 | inspect/restore 可闭环 | 支持包中引用最近备份状态 |
| License | 不做 | 试用/正式/过期/无效状态可解释 |
| 数据出口 | 备份可用 | License 过期后仍可导出数据 |

## 5. 范围

### 5.1 C0 范围：商用加固

- 修复现有路由拆分后的接口稳定性问题。
- 增加 API 冒烟测试。
- 增加系统诊断结果的脱敏规则。
- 明确数据目录、备份目录、日志/诊断目录。
- 形成 v1.2.1-pilot 发布清单。
- 形成一票否决门禁：测试失败、备份失败、敏感信息泄露、安装包无法启动均不得交付。

### 5.2 C1 范围：Local Pilot 控制面

- 首次启动向导。
- License 离线导入和状态查看。
- 设置页：工作区、数据目录、版本通道、隐私和诊断开关。
- 支持包导出。
- 样例工作区初始化。
- 试点目标配置。
- 用户手册和实施手册补充。

## 6. 不做范围

C0-C1 不做：

- 在线支付和自动续费。
- 账号登录、云同步和多人协作。
- SSO、SCIM、企业 RBAC。
- 私有化部署控制台。
- 自动静默更新。
- 公开模板市场。
- 完整财务账务或发票系统。

## 7. 功能需求

### 7.1 首次启动向导

#### 用户故事

作为首次使用 Nomos 的客户，我希望打开应用后能选择自己的使用场景、数据目录和初始化模板，这样我不用理解内部数据结构也能开始试点。

#### 页面步骤

| 步骤 | 内容 | 必填 | 说明 |
|------|------|------|------|
| 欢迎 | 展示 Nomos 当前版本、试点定位 | 是 | 不做营销页，只做操作入口 |
| 选择场景 | OPC 项目交付、中小企业流程落地、数字员工试点 | 是 | 影响样例模板 |
| 数据目录 | 显示默认目录，允许修改 | 是 | 修改需显式确认 |
| 初始化模板 | 默认组织、默认流程、样例项目 | 否 | 可跳过 |
| 试点目标 | 目标流程/项目、负责人、结束日期 | 否 | 进入客户成功复盘 |

#### 验收

- 空数据首次启动时出现向导。
- 已完成向导后不重复弹出，可在设置中重新打开。
- 跳过初始化不会创建演示项目。
- 初始化失败不得写入半成品数据，必须有错误提示和审计。

### 7.2 License 状态和导入

#### 用户故事

作为客户管理员，我希望导入试用或正式 License，并清楚知道当前套餐、到期时间和受限能力。

#### License 状态

| 状态 | 定义 | 产品行为 |
|------|------|----------|
| trial | 本地试用期内 | 允许使用 Local Pilot 能力 |
| active | 正式授权有效 | 根据套餐开启能力 |
| expired | 授权过期 | 不锁死数据读取、备份和导出，限制新增高价值能力 |
| invalid | License 签名或字段无效 | 不写入本地 License，提示错误 |
| missing | 未导入 License | 默认进入试用或只读体验 |

#### License 文件字段

```json
{
  "licenseId": "lic_xxx",
  "customerName": "客户名称",
  "plan": "pilot",
  "features": ["local_pilot", "support_bundle"],
  "issuedAt": "2026-06-12T00:00:00.000Z",
  "expiresAt": "2026-07-12T00:00:00.000Z",
  "deviceLimit": 1,
  "releaseChannels": ["pilot"],
  "signature": "base64-signature"
}
```

#### 验收

- 无效 JSON、缺字段、过期、签名错误都必须给出不同错误。
- 导入无效 License 不改变当前 License。
- 过期状态仍允许备份、恢复、导出支持包和查看已有数据。
- License 明文中不得包含私钥或服务端签名密钥。

### 7.3 设置中心

#### 范围

- 工作区名称。
- 客户标识。
- 数据目录只读展示。
- 备份目录只读展示。
- 版本通道：internal、pilot、stable。
- 诊断开关：是否允许导出匿名环境信息。
- 隐私开关：支持包是否包含本地路径摘要。

#### 验收

- 设置变更必须写入审计。
- 版本通道不允许切到 License 未授权通道。
- 数据目录不在此版本直接迁移，避免数据移动风险。

### 7.4 支持包导出

#### 用户故事

作为客户管理员，我希望遇到问题时一键导出支持包，交给 Nomos 团队定位问题，同时不泄露 Token 或敏感数据。

#### 支持包内容

| 文件 | 内容 | 脱敏要求 |
|------|------|----------|
| `manifest.json` | 版本、数据版本、创建时间、客户标识、License 状态 | 不含签名原文 |
| `diagnostics.json` | 系统状态、项目数量、备份数量、Agent 连接状态 | 本地路径可哈希或截断 |
| `audit-sample.json` | 最近 100 条审计 | 移除 Token、Key、确认令牌 |
| `errors.json` | 最近错误和堆栈摘要 | 不含环境变量 |
| `data-shape.json` | 各数据数组数量和字段存在性 | 不导出客户正文内容 |

#### 验收

- 支持包不包含 `tokenHash`、`confirmationToken`、`apiKey`、`Authorization`、`ANTHROPIC_AUTH_TOKEN` 等敏感字段。
- 支持包导出动作写入审计。
- 支持包导出失败不影响业务数据。

### 7.5 样例工作区

#### 样例

| 样例 | 用途 | 内容 |
|------|------|------|
| OPC 项目交付 | 展示五阶段项目链路 | 目标、PRD、开发、测试、预览、验收 |
| LTC 轻量流程 | 展示流程模板和关口评审 | 4-6 阶段、角色责任、准入准出 |
| 数字员工草稿 | 展示组织和 Agent 建模 | Skill、岗位、硅基员工草稿前三步 |

#### 验收

- 生产空启动默认不创建样例。
- 只有用户在向导中确认初始化样例时才写入。
- 初始化样例可重复检测，不创建重复模板。

## 8. 数据模型

### 8.1 `settings`

```json
{
  "workspaceName": "我的 Nomos 工作区",
  "customerId": "local",
  "releaseChannel": "pilot",
  "onboardingCompleted": false,
  "diagnostics": {
    "includePathHash": true,
    "includeAuditSample": true

  "createdAt": "2026-06-12T00:00:00.000Z",
  "updatedAt": "2026-06-12T00:00:00.000Z"
}
```

### 8.2 `license`

```json
{
  "status": "trial",
  "plan": "pilot",
  "licenseId": null,
  "customerName": null,
  "features": ["local_pilot"],
  "issuedAt": null,
  "expiresAt": null,
  "lastCheckedAt": "2026-06-12T00:00:00.000Z",
  "importedAt": null

```

```json

  "createdAt": "2026-06-12T00:00:00.000Z",
  "reason": "manual",
  "redactionVersion": 1,
  "size": 12345
}
```

## 9. API 需求

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/settings` | 获取设置 |
| PATCH | `/api/settings` | 更新设置 |
| GET | `/api/license` | 获取 License 状态 |
| POST | `/api/license/import` | 导入 License |
| GET | `/api/onboarding` | 获取首次启动状态 |
| POST | `/api/onboarding/complete` | 完成或跳过向导 |
| POST | `/api/onboarding/init-samples` | 初始化样例工作区 |
| GET | `/api/support/bundles` | 列出支持包 |
| POST | `/api/support/bundles` | 创建支持包 |
| GET | `/api/support/bundles/:fileName` | 下载支持包 |

## 10. 验收标准

### C0 验收

- 当前测试套件全部通过。
- 新增 smoke 测试覆盖健康、工作区、项目、组织、流程、备份、诊断。
- 诊断和支持包相关脱敏测试通过。
- 文档中列出所有已知问题和回退方式。

### C1 验收

- 用户可完成首次启动向导。
- 用户可导入有效 License 并看到 active 状态。
- 用户导入无效 License 不破坏当前状态。
- 用户可导出支持包，并通过敏感字段扫描。
- 用户可确认初始化样例工作区，并创建首个项目。

## 11. 风险

| 风险 | 控制 |
|------|------|
| License 逻辑阻断客户数据访问 | 过期只限制新增高价值能力，不限制数据读取/备份/导出 |
| 支持包泄露敏感信息 | 默认最小化导出，敏感字段黑名单和自动扫描 |
| 首次启动向导写入半成品 | 初始化前创建保护快照，失败回滚 |
| 商用控制面拖慢 v1.3 | C1 只做离线 License 和本地设置，不做在线计费 |

## 12. 待确认事项

- License 公钥是否直接内置在客户端，还是通过构建时注入。
- 试用期默认 14 天还是 30 天。
- 支持包是否需要 zip 格式，还是先用目录导出。
- Windows 安装包是否从 portable 升级到 installer，C1 可先保持 portable。

# PRD：流程管理模块

## 背景

Nomos v1.1 将完成组织管理模块，用户能建模自己的 Skill 池、岗位和员工。但组织是静态的——它定义了"谁有能力做什么"，却没有定义"这些人按什么顺序、什么标准一起完成一件事"。

信息架构文档已定义流程层的模型：

- 三级分类：价值流（执行类）、使能流（赋能类）、支撑流（保障类）
- 项目是流程的一次运行实例
- 项目执行产生的产出、回执、异常、复盘和验收结果要回流到组织知识与流程优化

调研资料中已完成的工作：
- 华为 16 条一级流程的详细分析（`huawei_flows_analysis.md`，77KB）
- 客户需求到流程的映射表（`demand_to_flow_mapping.md`）
- 华为流程拆解方法论文档（`research_huawei_flows.md`）

本 PRD 的目标是让这些研究成果在产品中落地为可操作的流程管理能力。

## 用户与场景

### 主要用户

| 用户 | 特征 | 核心诉求 |
|------|------|---------|
| OPC 创业者 | 一人跑多条流程 | 把自己的工作流标准化，让 Agent 能接管重复环节 |
| 流程 Owner | 负责某条业务线的标准化 | 定义流程模板，让团队按统一标准执行 |
| 项目经理 | 需要为具体项目分配流程 | 创建项目时绑定流程模板，追踪项目在各阶段的进展 |

### 典型场景

**场景一：创建 LTC 轻量版流程**

一个 SaaS 公司的销售总监在 Nomos 中：
1. 创建一条"LTC 轻量版"流程，归类为价值流
2. 定义 4 个阶段：管理线索 → 管理机会点 → 管理合同执行 → 开票回款
3. 为每个阶段设置关口：商机立项评审、合同审批、回款确认
4. 为每个阶段配置角色：AR（客户经理）、SR（方案经理）、FR（交付经理）
5. 保存为流程模板，供所有销售类项目使用

**场景二：项目绑定流程**

产品经理创建一个新产品开发项目：
1. 创建项目时选择"IPD 轻量版"流程模板
2. 系统自动创建 5 个阶段：概念 → 计划 → 开发 → 验证 → 发布
3. 每个阶段自动关联流程模板中定义的角色和关口
4. 项目开始后，项目经理能看到当前项目在流程中的位置和待办

**场景三：流程优化闭环**

销售总监在季度复盘时：
1. 查看"LTC 轻量版"流程下所有项目的完成情况
2. 发现"商机评估"阶段的平均耗时最长，且 Agent 回执完成率低
3. 调整流程模板，给"商机评估"阶段增加新的硅节点（Agent 自动生成客户画像）
4. 更新后的流程模板自动应用到新建项目，已有项目可选择升级

## 要解决的问题

1. **流程不在系统中**：当前 Nomos 的五阶段是硬编码的交付链路，不是用户可定义的流程模板
2. **项目没有流程上下文**：项目不绑定任何流程，无法回答"这个项目在跑哪条流程的哪个阶段"
3. **关口形同虚设**：当前的人工验收是单一的"检查点"，不是有准入准出标准的关口评审
4. **流程无法复用**：每个项目从零配置阶段，不能从流程模板继承

## 成功指标

| 指标 | 当前基线 | 目标 |
|------|---------|------|
| 用户创建流程模板的完成率 | N/A | 创建后 80% 以上至少定义 3 个阶段 |
| 项目绑定流程模板的比例 | 0% | 90% 以上新建项目绑定流程模板 |
| 关口评审执行率 | N/A | 所有绑定流程的项目 100% 经过关口评审 |
| 流程模板复用率 | N/A | 一个模板平均被 3 个以上项目使用 |

## 本版范围

### 流程库

- 流程模板 CRUD：名称、描述、分类（价值流/使能流/支撑流）、标签
- 流程模板列表：按分类浏览、搜索、筛选
- 流程模板详情：阶段列表、关口定义、角色配置、输入输出
- 预设模板：提供"LTC 轻量版"、"IPD 轻量版"、"ITR 轻量版"三个开箱即用的流程模板
- 流程使用统计：被多少项目使用、各阶段平均耗时

### 流程模板编辑

- 阶段序列：定义流程的阶段列表和顺序（创建/编辑/排序/删除）
- 关口节点：在每个阶段设置关口评审
  - 准入条件：进入此阶段前必须满足的条件（文本描述，v1.2 不做规则引擎）
  - 准出标准：离开此阶段必须达成的标准
  - 评审方式：碳评审（人工）/ 硅评审（Agent）/ 碳硅评审（Agent 预审 + 人工终审）
- 角色绑定：每个阶段绑定一个或多个角色（从组织管理的岗位中选择）
- 输入输出：每个阶段的输入材料和预期交付物

### 项目绑定流程

- 创建项目时选择流程模板（也可不选，保持当前自由模式兼容）
- 选择模板后自动生成项目阶段列表
- 项目阶段与流程阶段关联
- 支持在项目创建后更换流程模板（数据迁移）

### 关口评审

- 关口状态：待评审 / 通过 / 不通过 / 需返工
- 提交评审：提交者填写评审说明，附上交付物
- 评审执行：按评审方式执行（人工确认 / Agent 自动校验 / Agent 预审 + 人工终审）
- 评审结果：通过（自动进入下一阶段）/ 不通过（返回当前阶段）/ 需返工（返回指定阶段）

### 流程管理页面

- 独立页面入口：从首页"流程"区进入
- 流程库浏览：按分类展示流程模板
- 流程模板编辑器：拖拽排序阶段、配置关口和角色
- 项目实例追踪：显示所有绑定流程的项目的当前阶段和关口状态

## 不做范围

- 不做 L2-L5 五级完整分层（留到 v2.0 Workflow 引擎升级）
- 不做碳硅节点标注（留到 v2.0）
- 不做跨流程编排和子流程调用
- 不做流程仿真、瓶颈分析和 SLA 监控
- 不做流程版本 diff 和变更历史
- 不做规则引擎（准入准出条件为文本描述，不做可执行的规则校验）
- 不做流程模板市场或跨企业共享

## 交互流程

### 创建流程模板

```
流程页面 → 新建流程 → 填写名称/描述/分类 →
  添加阶段（拖拽排序）→
  为每个阶段配置关口（准入条件/准出标准/评审方式）→
  为每个阶段绑定角色 →
  保存
```

### 项目绑定流程

```
创建项目 → 选择流程模板（可选）→ 系统自动生成阶段列表 → 确认 → 项目开始
```

### 关口评审

```
项目执行到关口 → 提交评审 →
  [人工评审] 填写评审意见 → 通过/不通过/返工
  [Agent 评审] Agent 自动校验准出标准 → 生成评审结果 → 人工确认
  [碳硅评审] Agent 预审 → 人工终审 → 通过/不通过/返工
```

## 数据与权限

### 数据模型

```
flow-template: {
  id, name, description, category: 'value' | 'enabling' | 'supporting',
  tags[], stages: [{
    id, name, order, description,
    gate: {
      entryConditions: string,    // 准入条件（文本描述）
      exitCriteria: string,       // 准出标准
      reviewMode: 'carbon' | 'silicon' | 'hybrid',
      requiredRoles: string[]     // 评审角色
    },
    inputMaterials: string[],
    expectedOutputs: string[],
    roleBindings: [{
      roleId, raciRole: 'R' | 'A' | 'C' | 'I'
    }]
  }],
  createdAt, updatedAt
}

project: {
  // 现有字段...
  flowTemplateId?,     // 绑定的流程模板
  flowStages: [{        // 从模板实例化的阶段
    id, stageTemplateId, name, order,
    gateStatus: 'pending' | 'passed' | 'failed' | 'returned',
    gateReview: { reviewer, comment, reviewedAt }
  }]
}
```

### 存储方式

沿用当前单一 `nomos-data.json` 文件持久化方式，不新增独立 JSON 文件。在 `data` 对象中新增 `flowTemplates` 数组，现有 `projects[]` 增加 `flowTemplateId` 和 `flowStages` 字段，向后兼容（无模板时行为不变）。通过 `migrateData()` 版本升级自动补全 `flowTemplates: []`。

### 权限规则

- 所有流程数据为全局读写
- 删除流程模板时检查是否有项目正在使用，给出提示
- 更换项目的流程模板时提示数据可能不一致

## 验收标准

### 自动化测试

- 流程模板 CRUD 测试
- 项目绑定/更换流程模板测试
- 关口评审状态流转测试
- 删除被引用流程模板的关联检查测试
- 向后兼容测试（无模板项目行为不变）

### 手工验收

- 创建一条包含 4 阶段、3 关口的"LTC 轻量版"流程模板
- 新建项目绑定该模板，确认阶段自动生成
- 完整走完一个关口的评审流程（提交 → 通过 → 进入下一阶段）
- 评审不通过时正确返回当前阶段
- 不绑定模板的项目行为与 v1.0.1 一致

## 风险与回退

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 流程模板编辑器过于复杂 | 用户不会用 | 提供预设模板，允许简单模式（只填名称和阶段列表） |
| 项目绑定流程模板后数据迁移出问题 | 数据不一致 | 更换模板时提示并支持手动调整阶段映射 |
| 关口评审与现有工作流状态机冲突 | 代码复杂度增加 | 关口作为工作流状态机的扩展，不替换现有状态机 |

## 与现有代码的衔接

- `backend/workflow.js`：五阶段状态机保持不变，流程模板的阶段列表作为状态机的配置源
- `backend/agent-router.js`：路由器增加"当前流程阶段"作为路由依据之一
- `renderer/app.js`：新增流程管理页面 Tab，在项目创建流程中增加模板选择
- `renderer/index.html`：新增流程管理页面 UI

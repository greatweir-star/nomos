# nomos：Agent 项目指挥台

## 1. 文章研究结论

参考文章描述的是一个多 Agent 协作产品。它的价值不在于单个 Agent 更聪明，而在于把复杂任务拆给不同角色，在同一条链路中持续接力：

- 总管 Agent 负责拆任务、调度、检查质量和决定下一步。
- 专业 Agent 负责产品、设计、开发、测试、部署或内容运营等专项工作。
- 本地 Agent 可以接入 Claude Code、Codex CLI、OpenClaw，承担云端无法完成的代码仓库、文件系统和桌面环境操作。
- 人可以在关键节点介入，补充要求、修改结果或完成最终验收。
- 同一套机制既适合开发项目，也适合内容生产流水线。

文章原型采用“项目群聊 + 后台任务 + 本地 Agent 配对”的形态。它已经证明了协作链路，但仍有一个明显问题：当任务复杂度上升时，只看消息流很难快速判断当前阶段、阻塞原因和下一次需要人工介入的时机。

## 2. 产品定义

nomos是面向个人创作者、小团队和一人公司的 Agent 项目指挥台。用户只需要描述目标，系统就可以组织一组云端和本地 Agent 完成工作，并在必要时把决策权交还给用户。

一句话定位：

> 目标由人确定，过程由 Agent 接力，关键结果由人验收。

## 3. 设计原则

1. **项目优先，不是聊天优先。** 聊天是补充要求的入口，项目阶段才是主视图。
2. **过程可见。** 每个阶段都要显示责任 Agent、状态、交付物和下一步。
3. **人工验收明确。** 不让用户持续盯进度，只在关键检查点打扰用户。
4. **云端与本地统一调度。** 本地工具不是外挂，而是团队成员。
5. **权限逐级确认。** 本地文件写入、命令执行、外部发布等高权限动作要再次确认。

## 4. 首版信息结构

- 工作区：项目列表、Agent 团队、本地桥接状态。
- 项目总览：目标、交付链路、实时动态、人工验收点。
- 执行详情：当前任务进度、本地 Agent、项目资料。
- 协作记录：完整消息流和任务事件。
- 项目资料：PRD、设计稿、代码地址、发布记录。
- 规则与权限：验收条件、自动流转规则、本地权限。

## 5. MVP 范围

首版建议只做一条最容易验证价值的开发链路：

`提出目标 -> 总管拆解 -> PRD -> 设计 -> 本地开发 -> 测试 -> 预览发布 -> 人工验收`

必须具备：

- 新建项目并描述目标。
- 创建或选择 Agent 角色。
- 阶段化任务看板。
- 消息流与任务状态同步。
- 本地 Agent 桥接、识别和权限确认。
- 阶段交付物上传和人工验收。
- 失败任务回流给上游 Agent。

暂时不做：

- 复杂的可视化工作流编辑器。
- 多组织计费与企业权限体系。
- 大规模 Agent 市场。
- 同时支持过多业务模板。

## 6. 原型说明

打开 `prototype/index.html` 可以查看可点击桌面端原型。

可体验的交互：

- 点击左侧三个项目，查看目标变化。
- 点击五个交付阶段，查看右侧执行详情。
- 点击“接入本地 Agent”或左下角“管理”，打开本地桥接弹窗。
- 点击顶部标签，查看预留页面入口。

## 7. 下一步

进入开发前，建议先补三份文档：

1. 一条真实项目链路的详细状态机。
2. 云端总管与本地执行器之间的消息协议。
3. 高权限动作的确认清单和审计记录规则。

## 8. 当前开发进度

已经进入工作流闭环开发：

- 阶段支持结构化任务回执：进度、完成、失败和取消。
- 每次阶段接力生成可追踪任务信封，记录负责人、轮次、输入资料和回执状态。
- 交付物绑定到具体阶段，并随阶段卡片显示数量。
- 设计与发布阶段提交成果后进入人工验收；批准后继续接力，驳回后回到责任 Agent。
- 本地开发执行成功后自动生成回执并交接测试阶段。
- 阶段失败后进入阻塞态，可以按建议路径退回当前阶段或上游阶段返工。
- Alice MCP 已支持受控任务派发：预览发送内容、用户明确确认、派发状态记录、审计日志和同轮重复派发保护。
- Alice、Codex CLI 和 Claude Code 已开始共用统一 Agent 协议；OpenClaw 仅保留未启用的网关适配器占位。
- 工作流详情展示路由预览，让用户在派发前理解推荐 Agent、派发方式和回执来源。

仍待开发：

- Alice 总管的回执解析和云端模型接入。
- 测试报告解析、预览部署和正式发布确认。
- 团队、自动化和资料库的跨项目视图。

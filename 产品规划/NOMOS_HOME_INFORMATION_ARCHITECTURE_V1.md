# Nomos 首页信息架构 V1

## 设计命题

Nomos 首页不是普通项目看板，而是企业 OS 的控制台。V1 首页围绕一句话组织信息：

> 能力建在组织上，组织跑在流程上，企业运转透明可控。

因此首页分成三大部分：

1. 概览：显示企业脑当前运行态势，包括项目、员工、技术架构、验收待办。
2. 组织：显示公司 OS 的架构层，包括 Skill 池、岗位、碳硅员工、底层技术架构。
3. 流程：显示公司 OS 的业务流，包括流程体系、关口标准、项目实例和回流机制。

## 首页三区结构

### 1. 概览

概览回答“现在企业 OS 是否健康运行”。

关键对象：

- 当前阶段：项目正在跑到哪个关口。
- 碳硅员工：多少员工在线，多少硅基员工可用。
- 技术架构：多少 Agent/Adapter 已接入。
- 人工验收：哪些流程关口需要人类确认。

设计原则：

- 概览不展示所有细节，只显示决策所需的信号。
- 所有状态都能继续下钻到组织、流程或项目执行详情。

### 2. 组织

组织是公司 OS 的架构层。它的层级是：

Skill Pool -> Role -> Employee -> Technical Adapter

解释：

- Skill Pool：企业可复用的能力资产，需维护技能名称、等级、证据、适用流程和风险边界。
- Role：岗位是多个 Skill 的稳定组合，定义职责、权限、验收标准和流程位置。
- Employee：员工是岗位的承担者，可以是碳基、硅基或混编。
- Technical Adapter：底层技术架构是硅基员工调用能力的实现层，如 CodeX、Claude Code、Alice、OpenClaw、腾讯云端智能体等。

数字员工生成不是“接入一个工具”，而是把一个职场小白训练成可上岗的专业数字员工。它应放在组织模块内部，作为 Skill、岗位、知识、流程、工具、权限和性格的装配流程。

首页组织区的布局应采用左右结构：左侧展示组织建模，右侧整栏展示数字员工生成工厂。生成工厂顶部用 6 个步骤 Tab 呈现，点击任一步骤后，下方区域同步切换该步骤的目标、责任角色、配置项、阶段产出和风控边界。

六步生成数字员工：

1. 岗位匹配：配置目标技能，明确岗位职责、Skill 等级、输入输出和验收标准。
2. 入职培训：学习专业知识，绑定企业知识库、业务语料、行业规则和历史案例。
3. 师父带教：定义工作流程，由资深员工、流程 Owner 或岗位负责人沉淀 SOP 与示范样例。
4. 分配工具：关联终端设备、业务系统、API、数据源、自动化脚本和可调用智能体。
5. 上手实习：获取受控工作权限，在沙盒、低风险任务或人工复核场景中形成回执证据。
6. 转正上岗：赋予专属性格、协作风格、风险边界和升级机制，成为专业数字员工。

数字员工生成底座：

- 自定义层：技能自定义、知识自定义、流程自定义、权限自定义、性格自定义。
- AI 汇聚平台：大模型、智能体、行业应用、工具链和高质量数据集。
- 感知与操控：麦克风、摄像头、传感器、智能终端、AGV、机械臂等可选设备。
- 承载层：云、边缘服务器、边缘网关、专用智能设备。

在 Nomos 中，数字员工转正后必须同时拥有两重身份：

- 员工身份：属于哪个岗位，承担什么职责，在哪些流程上工作，由谁验收。
- 技术架构身份：底层由哪个 Adapter 或 Agent 能力实现，如 CodeX、Claude Code、Alice、OpenClaw 或云端智能体。

岗位类型：

- 纯碳基岗位：需要高信任、人际判断、复杂商业判断或合规签字。
- 纯硅基岗位：高重复、可标准化、可验证、低风险或有清晰回滚机制。
- 碳硅混编岗位：由人类承担责任，硅基承担信息处理、生成、检查、执行或监控。

### 3. 流程

流程是公司 OS 的业务流。项目不是孤立任务，而是流程的一次运行实例。

流程层级建议：

- 价值流：直接创造客户价值，如 MTL、LTC、IPD、ITR。
- 使能流：提升价值流效率，如战略到执行、管理变革、知识治理、平台能力供给。
- 支撑流：保障组织运行，如人力、财务、法务、IT、安全、采购和行政。

项目与流程关系：

- 流程定义模板、关口、岗位责任、输入输出、验收标准和风险控制。
- 项目继承流程模板，并在具体时间、目标、人员、资料和交付物上实例化。
- 项目执行过程中产生的产出、回执、异常、复盘和验收结果，要回流到组织知识与流程优化。

## 岗位规模建议

以下不是绝对编制标准，而是 Nomos V1 的默认组织建模建议。企业应按业务复杂度、监管强度、产品线数量和区域跨度调整。

| 企业规模 | 人数参考 | 推荐岗位数 | 技能池规模 | 组织建模重点 |
| --- | ---: | ---: | ---: | --- |
| OPC / 微型 | 1-9 人 | 5-8 个岗位 | 20-40 项 Skill | 多岗合一，先覆盖创始人、增长、交付、客户、财务法务、AI 运营 |
| 小微企业 | 10-50 人 | 8-15 个岗位 | 40-80 项 Skill | 明确获客、销售、交付、客户成功、经营支持的责任边界 |
| 中型企业 | 50-300 人 | 15-35 个岗位 | 80-200 项 Skill | 建立岗位族、流程 Owner、共享专家与硅基副驾 |
| 大型企业 | 300+ 人 | 35-80+ 个岗位 | 200+ 项 Skill | 按岗位族、区域、产品线、平台 COE、流程治理分层 |

默认岗位族建议：

- 经营与战略：CEO/总经理、战略负责人、经营分析、流程 Owner。
- 市场与增长：市场、内容、投放、品牌、公关、渠道。
- 销售与客户：销售、售前、客户成功、客服、续约。
- 产品与研发：产品、设计、研发、测试、数据、架构。
- 交付与运营：项目经理、交付、运维、供应链、质量。
- 职能支撑：人力、财务、法务、行政、采购、安全。
- AI 与平台：智能体管理员、知识库管理员、AgentOps、数据治理、权限审计。

## V1 首页落地范围

已进入客户端首页：

- 企业 OS 主张：能力建在组织上，组织跑在流程上，企业运转透明可控。
- 三大入口：概览、组织、流程。
- 组织层模型：Skill Pool、Role、Employee。
- 员工类型：碳基、硅基、混编。
- 岗位规模建议：OPC/微型、小微、中型、大型。
- 流程层模型：价值流、使能流、支撑流。
- 项目流程关系：项目是流程的一次运行实例。

后续应继续开发：

- 独立组织管理页面：Skill 池维护、岗位模板、员工任命、岗位-流程矩阵。
- 独立流程管理页面：流程库、关口标准、RACI、SOP、项目实例追踪。
- Agent 身份治理：员工身份与底层技术架构分离，支持多供应商云端智能体。
- 组织诊断：根据公司规模、业务类型和当前流程，自动提示岗位缺口与 Skill 缺口。

## 参考框架

- SFIA：用于理解 Skill、责任等级和能力证据化。
- Team Topologies：用于理解围绕价值流组织团队，并控制认知负载。
- APQC PCF：用于理解企业流程分类和流程资产化。
- 华为 IPD/LTC/ITR 等流程型组织实践：用于理解“流程先行、项目运行在流程实例上”的企业级管理思路。

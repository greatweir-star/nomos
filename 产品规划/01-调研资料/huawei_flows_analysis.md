### 分析维度定义

每个流程按以下8个维度进行分析：

| 维度 | 说明 |
|------|------|
| 流程概述 | 该流程要解决什么问题，核心价值是什么 |
| 流程环节 | 按L2-L3层级列出主要阶段和关键任务 |

### 华为流程体系整体框架

华为业务流程体系通常被归纳为16-17个一级流程（不同版本略有差异），可分为三大类：

**运营流程（Operating Processes）**：直接面向客户价值创造
- IPD（集成产品开发）
- MTL（市场到线索）
- LTC（线索到回款）
- ITR（问题到解决）
- CRS（渠道零售服务）
- IPMS（集成产品营销与销售，消费者BG特有）

**使能流程（Enabling Processes）**：支撑运营流程高效运作
- DSTE（开发战略到执行）
- MCR（管理客户关系）
- Supply/ISC（供应/集成供应链）
- Procurement（采购）
- SD（服务交付）
- MCI（管理资本投资）

**支撑流程（Supporting Processes）**：提供基础资源和能力保障
- MHR（管理人力资源）
- MF/IFS（管理财经/集成财经服务）
- BT&IT（业务变革与IT）
- MBS（管理基础支撑）
- MQ（管理质量）

## 1. IPD（集成产品开发，Integrated Product Development）

### 流程概述

IPD是华为最核心的业务流程，源于1999年IBM咨询引入，经华为本土化改造后成为全球研发管理的标杆范式。其核心目标是**将研发从"艺术"变为"科学"**，通过结构化的流程、跨部门团队协作和分阶段投资决策，实现"做正确的事"和"正确地做事"的统一。

**核心价值**：
- **商业成功导向**：IPD不是单纯的技术开发流程，而是以商业成功为最终目标的产品投资流程
- **跨部门协同**：打破部门墙，通过PDT（产品开发团队）实现研发、市场、供应链、服务等端到端协同
- **分阶段控风险**：通过TR（技术评审）和DCP（决策评审）实现"早期发现问题、早期解决问题"
- **重用与平台化**：通过CBB（共用构建模块）最大化技术资产复用

据部分公开资料称，IPD实施后产品上市成功率从30%提升至75%，研发周期缩短30%-50%（待确认）。

### 流程环节

IPD流程在L1层级分为6个阶段，在L2-L3层级展开为更详细的任务活动。

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 概念阶段 │ → │ 计划阶段 │ → │ 开发阶段 │ → │ 验证阶段 │ → │ 发布阶段 │ → │ 生命周期│
│ (Concept)│   │ (Plan)  │   │(Develop)│   │(Qualify)│   │(Launch) │   │ (Life)  │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
     ↑                                                                      ↓
     └──────────────────────────────────────────────────────────────────────┘
                              流程闭环与知识反馈
```

**L2-L3详细环节**：

| 阶段 | L2环节 | L3关键任务 |
|------|--------|-----------|

### 角色（Roles）

IPD采用**重量级团队（Heavyweight Team）**模式，核心角色如下：

| 角色 | 职责 | 组织归属 |
|------|------|----------|
| **IPMT**（集成组合管理团队） | 产品投资组合决策、DCP决策评审、资源分配、战略对齐 | 跨部门高层委员会 |
| **PDT经理**（产品开发团队经理） | 对项目商业成功负责，端到端项目管理，跨部门协调 | 通常来自研发/市场，全职投入 |
| **研发代表** | 技术方案实现、开发进度管理、技术风险把控 | 研发部门 |
| **市场代表** | 市场需求定义、竞品分析、上市策略、定价建议 | 市场部门 |
| **供应链代表** | 可制造性设计、供应商选择、产能规划、成本优化 | 供应链部门 |
| **服务代表** | 可服务性设计、技术支持方案、客户培训材料 | 服务部门 |
| **质量代表** | 质量策划、测试策略、缺陷管理、质量标准执行 | 质量部门 |
| **财务代表** | 项目投资测算、成本控制、盈利能力分析 | 财务部门 |
| **采购代表** | 物料选型、供应商认证、采购成本谈判 | 采购部门 |

**华为IPD团队演进模式**：从功能型组织 → 轻量级团队 → 重量级团队 → 自主经营体（铁三角在LTC中更典型，IPD中体现为PDT的端到端负责）。

### Checkpoint/关口

IPD的评审体系是"双轨制"：TR（技术评审）+ DCP（决策评审）。

**TR评审（Technical Review）——技术质量把关**：

| TR节点 | 评审时机 | 核心内容 | 通过标准（典型值） |
|--------|----------|----------|-------------------|
| **TR1** | 概念阶段末 | 产品包需求完备性、概念技术可行性 | 需求覆盖率>=90%，技术可行性评分>=6/10 |
| **TR2** | 计划阶段初 | 设计规格完整性、架构合理性、DFX达标 | 规格与需求匹配度>=95% |
| **TR3** | 计划阶段末 | 概要设计完整性、模块接口清晰、风险应对方案 | 接口一致性>=90%，风险覆盖率100% |
| **TR4** | 开发阶段中 | 构建模块功能达标、单元测试通过 | 缺陷密度<=0.5/千行，覆盖率>=90% |
| **TR4A** | 开发阶段末 | 原型机技术成熟度、量产准备度 | 性能指标达成率>=95% |
| **TR5** | 验证阶段中 | 系统测试通过率、量产验证结果 | 测试通过率>=99%，试产直通率>=95% |
| **TR6** | 验证阶段末 | 量产能力、全球交付能力、合规性 | 量产准备度>=90%，无重大合规风险 |

**DCP评审（Decision Check Point）——投资决策把关**：

| DCP节点 | 评审时机 | 决策内容 | 决策选项 |
|---------|----------|----------|----------|
| **CDCP**（概念决策评审） | 概念阶段结束 | 是否批准项目进入计划阶段 | Go / No Go / Redirect |
| **PDCP**（计划决策评审） | 计划阶段结束 | 是否批准项目进入开发阶段，批准预算和资源 | Go / No Go / Redirect |
| **ADCP**（可获得性决策评审） | 开发/验证阶段结束 | 是否批准产品发布上市 | Go / No Go / Redirect |
| **LDCP**（生命周期决策评审） | 生命周期末期 | 是否退市、迭代或延续 | 退市 / 升级 / 延续 |

**评审协同机制**：
- TR评审为DCP提供技术可行性依据（如TR4A数据支撑ADCP量产决策）
- DCP为TR设定资源边界（如CDCP批准的预算决定技术方案选择范围）
- PDT同步准备两类评审材料，IPMT在DCP中参考TR结论

### 知识归档

| 阶段 | 知识资产 | 归档方式 |
|------|----------|----------|
| 概念阶段 | 市场洞察方法论、需求分析模板、$APPEALS评估记录 | 存入市场洞察知识库 |
| 计划阶段 | 系统架构设计模式、接口规范、DFX检查清单 | 存入技术平台/架构知识库 |
| 开发阶段 | 代码规范、模块设计模式、测试用例库、缺陷模式库 | 存入研发知识管理系统 |
| 验证阶段 | 测试方案模板、认证经验、Beta客户反馈模式 | 存入测试与认证知识库 |
| 发布阶段 | 上市 checklist、营销材料模板、培训课件 | 存入GTM（Go-To-Market）知识库 |
| 生命周期 | 客户问题根因分析、优化案例、退市经验 | 存入运营与售后知识库 |

**组织记忆机制**：
- **CBB库（共用构建模块）**：可复用的技术模块、组件、平台
- **Lesson Learned库**：项目复盘结论，强制要求每个TR和DCP后更新
- **专家系统**：将资深工程师的经验固化到评审checklist和评审指南中

### 碳硅重构建议

| 环节类型 | 具体环节 | 重构建议 | 理由 |
|----------|----------|----------|------|
| **硅节点（Agent执行）** | 需求相似度分析、CBB匹配推荐 | 高适合度 | 基于历史产品包需求库，Agent可自动匹配相似需求并推荐复用CBB |
| | TR评审材料预审 | 高适合度 | Agent可自动检查需求覆盖率、文档完整性、格式合规性 |
| | 测试用例生成、缺陷模式识别 | 高适合度 | 基于历史测试数据和缺陷库，Agent自动生成测试用例并预测高风险模块 |
| | 财务模型测算、ROI敏感性分析 | 中适合度 | Agent可快速运行多场景财务模型，但最终判断需人 |
| **碳节点（人执行）** | 产品概念创意生成 | 必须人工 | 突破性创新依赖人的洞察力和创造力 |
| | DCP投资决策 | 必须人工 | 涉及战略判断、资源分配、风险承受度，需高层决策 |
| | 客户Beta测试沟通 | 必须人工 | 需要建立信任关系，理解客户隐性需求 |
| | 跨部门冲突协调 | 必须人工 | PDT经理的政治智慧和谈判能力难以被替代 |
| **碳硅混合** | 需求优先级排序 | 混合 | Agent提供数据支撑（市场规模、技术可行性评分），人做最终权衡 |
| | 技术方案选择 | 混合 | Agent做多方案仿真和对比，人做创新性和战略适配判断 |
| | 风险评估 | 混合 | Agent识别已知风险模式，人识别新型风险和系统性风险 |
| | 项目计划制定 | 混合 | Agent生成初版WBS和关键路径，人调整资源冲突和里程碑逻辑 |

## 2. MTL（市场到线索，Market to Lead）

### 流程概述

MTL是华为"营"的核心流程，解决的是**"如何让客户产生购买意愿"**的问题。与LTC（销售流程）不同，MTL聚焦在"营"而非"销"——即通过市场活动、品牌建设、需求激发，将潜在客户从"认知"推进到"有兴趣"（线索）状态。

**核心价值**：
- **市场驱动**：确保销售线索不是随机产生，而是基于系统化的市场策划
- **品牌与效果统一**：MTL既负责品牌长期建设，也负责短期线索产出
- **细分市场深耕**：通过SAMP（细分市场计划）实现精准营销
- **线索质量保障**：通过线索评级和培育机制，向LTC输出高质量线索

MTL与LTC的衔接点：**线索（Lead）**。MTL输出MQL（Marketing Qualified Lead，市场认可线索），LTC接收并转化为SQL（Sales Qualified Lead，销售认可线索）。

### 流程环节

```
市场洞察 → 细分市场选择 → 市场策略制定 → 营销Campaign策划 → 线索生成 → 线索培育 → 线索移交(LTC)
```

**L2-L3详细环节**：

| L2环节 | L3关键任务 | 说明 |
|--------|-----------|------|
| **市场洞察** | 宏观环境分析（PEST）、行业趋势研究、客户行为分析、竞品动态监控 | 输出《市场洞察报告》 |
| | 客户声音（VOC）收集 | 客户访谈、NPS调研、社交媒体监听 |
| **细分市场管理** | 市场细分（Segmentation）、目标市场选择（Targeting）、价值定位（Positioning） | STP模型应用 |
| | 细分市场计划（SAMP）制定 | 每个目标细分市场制定专属GTM计划 |
| **营销战略规划** | 年度营销目标设定、预算分配、品牌策略、数字营销策略 | 与DSTE战略对齐 |
| **Campaign策划** | 主题创意、内容策划、渠道选择、活动排期 | Campaign分为品牌型和效果型 |
| | 内容生产 | 白皮书、案例研究、视频、Webinar、社交媒体内容 |

## 3. LTC（线索到回款，Lead to Cash）

### 流程概述

LTC是华为最核心的销售流程，解决**"如何将销售线索转化为收入和现金"**的问题。华为著名的"铁三角"（AR、SR、FR）模式就是诞生于LTC流程。LTC强调以项目为中心，端到端地管理从线索发现到合同签订、交付验收、回款完成的完整销售周期。

**核心价值**：
- **端到端打通**：打破销售、交付、财务的部门墙，实现"一条线拉通"
- **铁三角协同**：AR（客户经理）+ SR（解决方案经理）+ FR（交付经理）形成"接口归一、力出一孔"的客户界面
- **风险前置**：在投标和合同签订前识别交付风险、财务风险、法律风险
- **可复制的成功**：将标杆项目的成功经验固化为流程、模板和打法

**LTC与MTL、ITR的关系**：
- MTL输出线索给LTC
- LTC在交付阶段可能需要ITR的技术支持
- ITR处理的问题可能转化为新的线索或增购机会

### 流程环节

```
管理线索 → 管理机会点 → 管理投标/谈判 → 管理合同 → 管理交付 → 管理回款
```

**L2-L3详细环节**：

| L2环节 | L3关键任务 | 说明 |
|--------|-----------|------|
| **管理线索** | 线索接收与确认 | 接收MTL移交的MQL，转化为销售线索 |

| | 需求分析与方案设计 | 深度理解客户需求，制定差异化解决方案 |
| | 竞争分析 | 竞品对标、竞争策略制定、赢单率评估 |
| | 商业模式设计 | 定价策略、付款条款、风险分担机制 |

| **管理合同** | 合同评审与签订 | 法务、财务、交付多部门会签 |
| | 合同交底 | 向交付团队移交合同关键条款和客户需求 |

| | 项目关闭 | 财务结算、经验总结、知识归档 |

## 4. ITR（问题到解决，Issue to Resolution）

### 流程概述

ITR是华为的客户服务与技术支持流程，解决**"如何快速有效地解决客户问题，恢复客户业务，并持续提升客户满意度"**的问题。ITR覆盖从客户问题受理、诊断、解决到闭环的完整服务周期。

**核心价值**：
- **客户满意度保障**：快速响应和解决问题是客户续约和增购的基础
- **产品改进输入**：将客户问题反馈给IPD，驱动产品持续优化
- **服务收入创造**：通过技术支持服务、维保服务创造持续收入
- **品牌口碑维护**：在危机时刻（如网络故障）的快速恢复能力是品牌核心资产

**ITR与LTC、IPD的闭环**：
- 问题单中的产品缺陷反馈给IPD进行产品改进
- 问题处理过程中的客户关系维护为LTC创造增购机会
- 重大问题的解决方案可沉淀为知识资产

### 流程环节

```
问题受理 → 问题分类与分级 → 问题诊断 → 方案制定与实施 → 验证关闭 → 复盘改进
```

**L2-L3详细环节**：

| L2环节 | L3关键任务 | 说明 |
|--------|-----------|------|
| **问题受理** | 多渠道接入 | 热线、邮件、在线工单、客户门户、自动告警 |
| | 工单创建与信息录入 | 客户信息、问题描述、影响范围、紧急程度 |
| | 客户沟通与期望管理 | 首次响应、告知处理流程、设定预期时间 |
| **问题分类与分级** | 问题分类 | 技术类/商务类/操作类/外部原因 |
| | 优先级定级 | 根据影响范围、紧急程度分为P1/P2/P3/P4 |
| | 工单分派 | 根据问题类型分配给对应技术支持团队 |
| **问题诊断** | 远程诊断 | 日志分析、远程登录、复现测试 |
| | 现场支持（如需） | 派遣工程师到现场 |

| | 永久解决方案 | 补丁、升级、替换、配置优化 |
| | 变更实施 | 在客户环境中实施方案 |
| **验证关闭** | 客户验证 | 确认问题已解决、业务恢复正常 |
| | 工单关闭 | 记录解决方案、关闭工单 |
| | 满意度回访 | NPS或满意度评分 |
| **复盘改进** | 根因分析（RCA） | 5Why、鱼骨图等分析方法 |

## 6. DSTE（开发战略到执行，Develop Strategy To Execute）

### 流程概述

DSTE是华为的战略管理流程，解决**"如何制定正确的战略，并确保战略有效落地执行"**的问题。DSTE是华为管理体系的"龙头"，为所有其他流程（IPD、LTC等）提供方向指引和资源约束。

DSTE的核心方法论是**BLM（业务领先模型，Business Leadership Model）** + **BEM（业务执行力模型，Business Execution Model）**。BLM解决"战略设计"问题，BEM解决"战略解码"问题。

**核心价值**：
- **战略一致性**：确保公司、产品线、职能部门的战略上下对齐
- **资源聚焦**：通过战略解码，将有限资源投入到关键战略举措上
- **执行闭环**：通过战略回顾和执行监控，确保"说到做到"
- **动态调整**：根据市场变化快速调整战略方向和资源配置

### 流程环节

DSTE通常按年度周期运行，分为四个阶段：

```
战略制定（SP） → 战略解码（BEM） → 年度经营计划（BP） → 执行监控与复盘
```

**L2-L3详细环节**：

| L2环节 | L3关键任务 | 说明 |
|--------|-----------|------|
| **战略洞察** | 市场洞察（五看：看宏观/看行业/看客户/看竞争/看自己） | 输出机会与威胁清单 |
| | 差距分析 | 业绩差距（现实vs目标）、机会差距（现实vs可能） |
| | 战略意图澄清 | 愿景、长期目标、短期目标 |
| **战略制定（SP）** | 创新焦点设计 | 未来业务组合、创新路径 |
| | 业务设计 | 客户选择、价值主张、价值获取、活动范围、持续优势、风险管理 |
| | 正式战略文档 | 《战略规划（SP）》，覆盖3-5年 |
| **战略解码（BEM）** | 导出CSF（关键成功因素） | 从战略中提炼必须打赢的仗 |
| | 制定战略KPI | 将CSF转化为可衡量的指标 |
| | 识别CTQ-Y（关键质量特性） | 分解到可执行层面 |
| | 制定重点工作 | 年度必须完成的战略举措 |
| **年度经营计划（BP）** | 目标分解 | 公司目标→产品线目标→部门目标→个人目标 |
| | 预算编制 | 费用预算、投资预算、人力预算 |
| | 绩效承诺签订 | PBC（个人绩效承诺）签订 |
| **执行监控** | 月度运营分析 | 财务指标、销售指标、项目进展跟踪 |
| | 季度战略回顾 | 战略举措执行情况、差距分析、纠偏措施 |
| | 半年度/年度复盘 | 全面评估战略执行效果，输入下一轮SP |

### 输入

| 输入项 | 来源 |
|--------|------|
| 宏观环境数据（PEST） | 外部研究机构、行业报告 |
| 市场与竞争情报 | 市场部门、竞争情报系统 |
| 财务与运营数据 | IFS/财务部门 |
| 客户反馈与需求 | MTL、LTC、ITR流程 |
| 技术趋势 | 技术预研、IPD前沿探索 |
| 上一周期复盘结论 | DSTE上一轮输出 |

### 输出

| 输出项 | 说明 |
|--------|------|
| 《战略规划（SP）》 | 3-5年战略方向、业务设计、关键举措 |
| 《年度经营计划（BP）》 | 年度目标、预算、重点工作 |
| 战略KPI体系 | 公司级/产品线级/部门级KPI |
| PBC（个人绩效承诺） | 每个管理者的绩效合同 |

### 角色

## 7. MCR（管理客户关系，Manage Customer Relationship）

### 流程概述

MCR是华为的客户关系管理体系，解决**"如何系统化地管理客户关系，从陌生人变成可信赖的合作伙伴"**的问题。MCR不是简单的客户信息管理，而是一套涵盖客户洞察、关系规划、关键人管理、客户满意度的完整方法论。

华为将客户关系分为三个层次：
- **组织客户关系**：公司与公司之间的战略合作关系
- **关键客户关系**：与决策者、影响者的个人关系
- **普遍客户关系**：与执行层、使用层的广泛联系

**核心价值**：
- **降低商业风险**：通过深度关系提前获知客户决策动向和项目信息
- **提升赢单率**：关系深度与项目中标概率高度正相关
- **创造增购机会**：基于信任推出新方案、新服务
- **危机缓冲**：出现问题时，良好的客户关系是重要的缓冲垫

### 流程环节

| L2环节 | L3关键任务 |

| **关键人管理** | 关键人画像、关系深度评估、个人诉求匹配、信任建设 |

## 8. Supply/ISC（供应/集成供应链，Integrated Supply Chain）

### 流程概述

ISC是华为面向全球的集成供应链管理流程，解决**"如何在正确的时间、以正确的成本、将正确质量的产品交付到正确地点"**的问题。ISC涵盖从需求预测、计划、生产、物流到交付的完整供应链链条。

华为ISC经历了从"被动响应"到"主动预测"、从"区域分散"到"全球集成"的演进。核心能力包括：
- **全球供需平衡**：在全球范围平衡产能与需求
- **快速响应**：面对需求波动和供应中断的快速调整能力
- **成本优化**：通过规模效应和精益管理持续降本
- **质量保障**：来料质量、过程质量、交付质量的全流程管控

### 流程环节

| **仓储物流** | 入库、存储、拣配、包装、运输、清关 |
| **交付履行** | 交付计划、客户通知、签收确认 |
| **逆向物流** | 退货、返修、回收、环保处置 |

## 17. IPMS（集成产品营销与销售，Integrated Product Marketing & Sales）

### 流程概述

IPMS是华为消费者BG（终端业务）特有的流程，对标企业BG的IPD+MTL+LTC组合，但针对To C消费品业务特点进行了重新设计。IPMS将**产品规划、营销策划、渠道销售、零售运营**整合为一个端到端流程，核心目标是实现产品从规划到上市到退市的全生命周期商业成功。

IPMS与IPD的区别：
- IPD聚焦**技术实现和产品开发**
- IPMS聚焦**商业成功和GTM（Go-To-Market）**
- IPMS在消费者BG与IPD并行运行，IPMS经理对商业结果负总责

### 流程环节

| L2环节 | L3关键任务 | 说明 |

| | 商业计划制定 | 销量预测、定价策略、利润模型 |

### 碳硅协同重构原则建议

基于Nomos"碳硅协同"理念，对华为流程体系AI重构提出以下原则性建议：

1. **决策关口保留碳节点**：所有DCP、投资决策、合同谈判、人事任命等涉及重大资源分配和战略方向的关口，必须保留人的最终决策权。

2. **信息处理环节优先硅化**：需求分析、数据汇总、文档检查、合规比对、知识检索等信息密集型环节，是Agent最容易发挥价值的领域。

3. **客户关系保持碳主导**：MCR和LTC中的客户关系建设、信任积累、危机沟通等环节，人的情感智慧和政治判断力不可替代。

4. **重复性运营环节全面硅化**：ISC中的MRP计算、库存监控；IFS中的会计核算；ITR中的工单分派等标准化、重复性工作，应首先实现Agent化。

5. **混合环节设计"人机回环"**：方案设计、风险评估、根因分析等环节，设计为Agent生成初稿/建议，人做判断、修正和确认。

6. **知识流是硅化的基础**：华为已有的CBB库、知识库、案例库是Agent发挥价值的数据基础，需先完成知识的结构化和数字化。
